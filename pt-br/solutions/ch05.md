## Solução do Exercício 01

A operação não depende de uma entrada: sempre mostra a mesma mensagem. Por isso, os parênteses da definição ficam vazios. O `print` pertence ao corpo indentado; a chamada fica fora dele, para solicitar a execução depois que a função foi definida.

``` python
def iniciar_relatorio():
    print("Relatório iniciado.")

iniciar_relatorio()
```

``` text
Relatório iniciado.
```

A saída aparece por causa da chamada, não apenas da definição. Esta função comunica uma mensagem e chega ao fim sem `return` explícito; seu retorno é `None`. Não há necessidade de devolver uma quantidade neste exercício.

<a id="sol-ch05-02"></a>

## Solução do Exercício 02

A quantidade pode variar entre chamadas. Usamos `producao` como parâmetro e inserimos seu valor na mensagem com uma f-string. O texto “unidades” comunica a grandeza representada, sem fazer parte do número fornecido.

``` python
def mostrar_producao(producao):
    print(f"Produção: {producao} unidades")

mostrar_producao(850)
```

``` text
Produção: 850 unidades
```

`producao` é o parâmetro da definição; 850 é o argumento desta chamada. A função exibe 850 unidades, mas não devolve esse número como retorno. Uma nova quantidade poderia usar a mesma definição.

<a id="sol-ch05-03"></a>

## Solução do Exercício 03

A ordem da subtração foi explicitada no enunciado. O primeiro parâmetro representa a produção observada, e o segundo, a planejada. A variável local `diferenca` ajuda a ler o cálculo antes de exibir sua resposta.

``` python
def mostrar_diferenca(producao, planejado):
    diferenca = producao - planejado
    print(f"Diferença: {diferenca} unidades")

mostrar_diferenca(850, 800)
```

``` text
Diferença: 50 unidades
```

A diferença é positiva: foram produzidas 50 unidades além do planejado. A conta mede uma diferença absoluta, não uma taxa percentual. Inverter os argumentos alteraria seu sentido e não responderia à pergunta formulada.

<a id="sol-ch05-04"></a>

## Solução do Exercício 04

Multiplicar custo por unidade pela quantidade produz um custo total na mesma moeda. A função deve devolver o número; a formatação monetária fica fora dela. Assim, o resultado armazenado em `custo` pode participar de outro cálculo.

``` python
def calcular_custo_total(custo_unitario, quantidade):
    custo_total = custo_unitario * quantidade
    return custo_total

custo = calcular_custo_total(18.5, 240)
print(f"R$ {custo:.2f}")
```

``` text
R$ 4440.00
```

O retorno é 4440, correspondente a R\$ 4.440,00. A saída usa ponto decimal conforme a formatação do Python. O texto “R\$” é acrescentado apenas na exibição; `custo` continua sendo numérico.

<a id="sol-ch05-05"></a>

## Solução do Exercício 05

Este item depende do resultado anterior. Dividimos a parcela, `custo`, pelo todo usado como referência, `orcamento`, e multiplicamos por 100. As duas grandezas estão na mesma moeda e o orçamento informado é positivo.

``` python
orcamento = 5000
percentual_orcamento = custo / orcamento * 100
print(f"{percentual_orcamento:.2f}%")
```

``` text
88.80%
```

O custo corresponde a 88,80% do orçamento. O percentual descreve a relação entre os valores dados; não prova que o gasto foi eficiente. Reutilizar o retorno evita repetir a multiplicação de custo unitário por quantidade.

<a id="sol-ch05-06"></a>

## Solução do Exercício 06

Preço e desconto são entradas; a regra é a mesma nas três chamadas. Dividir o desconto por 100 o expressa como proporção. Subtrair essa proporção de 1 fornece a parcela do preço que permanece após o desconto, e a multiplicação produz o preço final.

``` python
def calcular_preco_com_desconto(preco, desconto):
    preco_final = preco * (1 - desconto / 100)
    return preco_final

print(calcular_preco_com_desconto(200, 10))
print(calcular_preco_com_desconto(350, 8))
print(calcular_preco_com_desconto(120, 5))
```

``` text
180.0
322.0
114.0
```

Os preços finais são 180, 322 e 114. As saídas com `.0` continuam representando valores numéricos. A função concentra a fórmula em uma definição, permite mudar as entradas e facilita revisar a regra sem procurar três cópias.

<a id="sol-ch05-07"></a>

## Solução do Exercício 07

A lista é uma entrada, e cada elemento é tratado pelo laço. `prazos` representa a coleção; `prazo`, um valor a cada iteração. Como o objetivo é apresentar os dados, usamos `print` dentro do laço sem construir um total.

``` python
def mostrar_prazos(prazos):
    for prazo in prazos:
        print(f"{prazo} dias")

mostrar_prazos([3, 5, 2, 7])
```

``` text
3 dias
5 dias
2 dias
7 dias
```

Os quatro prazos aparecem em sua ordem original, cada um com sua unidade. A função chega ao fim e retorna `None`; isso é adequado à tarefa de exibição. O exercício não pede média, soma ou alteração da lista.

<a id="sol-ch05-08"></a>

## Solução do Exercício 08

O contador começa em zero dentro da função. A comparação usa `<`, porque a pergunta exige estar abaixo do mínimo. Quando a condição é satisfeita, acrescentamos uma ocorrência, não o valor do estoque. O retorno fica depois da travessia.

``` python
def contar_estoques_baixos(estoques, estoque_minimo):
    contador = 0
    for estoque in estoques:
        if estoque < estoque_minimo:
            contador = contador + 1
    return contador

quantidade_baixa = contar_estoques_baixos([18, 7, 12, 5, 20], 10)
print(quantidade_baixa)
```

``` text
2
```

Os estoques 7 e 5 satisfazem a condição; o retorno é 2. Um valor exatamente igual ao mínimo não entraria nessa contagem. O resultado conta itens abaixo do limite, não unidades que faltam para completar o estoque.

<a id="sol-ch05-09"></a>

## Solução do Exercício 09

O acumulador começa em zero e incorpora cada valor. `return total` está alinhado com o `for`, fora do corpo do laço, para devolver a soma completa. A comparação com a função embutida usa a mesma lista, sem alterar seus elementos.

``` python
def calcular_total_manual(valores):
    total = 0
    for valor in valores:
        total = total + valor
    return total

valores = [45, 60, 55, 40]
print(calcular_total_manual(valores))
print(sum(valores))
```

``` text
200
200
```

As duas formas produzem 200. A igualdade confirma o resultado para a lista fornecida. A função manual expõe a lógica de acumulação; `sum()` é uma forma mais direta de realizar esta soma simples.

<a id="sol-ch05-10"></a>

## Solução do Exercício 10

A entrada é um estoque por chamada, e a saída é uma classificação textual. A comparação escolhe um dos dois caminhos de retorno. Igualar o mínimo pertence ao segundo caminho, pois a condição do primeiro é estritamente menor.

``` python
def classificar_estoque(estoque, estoque_minimo):
    if estoque < estoque_minimo:
        return "Reposição necessária"
    else:
        return "Estoque suficiente"

print(classificar_estoque(7, 10))
```

``` text
Reposição necessária
```

Como 7 é menor que 10, o resultado é “Reposição necessária”. A regra classifica a situação sob o critério didático; não calcula uma quantidade de compra ou considera demanda futura.

## Solução do Exercício 11

O nome escolhido informa a operação, e a primeira instrução do corpo é uma string que a documenta. Usamos `max` para obter o maior elemento e o devolvemos diretamente. Não precisamos implementar outra travessia quando uma função embutida já atende ao objetivo.

``` python
def encontrar_maior_tempo(tempos):
    """Retorna o maior tempo observado em uma lista."""
    return max(tempos)

print(encontrar_maior_tempo([12, 9, 15, 11]))
```

``` text
15
```

O retorno é 15. Não acrescentamos “minutos” ou “horas”, pois essa informação não foi fornecida. A forma de `max` usada aqui requer uma lista não vazia. Outros nomes claros e soluções corretas também atendem ao enunciado.

<a id="sol-ch05-12"></a>

## Solução do Exercício 12

Precisamos acompanhar duas informações sobre a mesma seleção. Dentro do `if`, o contador recebe mais uma ocorrência e o acumulador recebe o valor selecionado. Ao final, um dicionário associa cada resultado a um nome, reunindo-os em um único objeto retornado.

``` python
def resumir_valores_selecionados(valores, limite):
    quantidade = 0
    total = 0
    for valor in valores:
        if valor >= limite:
            quantidade = quantidade + 1
            total = total + valor
    return {"quantidade": quantidade, "total": total}

resumo = resumir_valores_selecionados([72, 88, 91, 65, 84], 80)
print(resumo)
```

``` text
{'quantidade': 3, 'total': 263}
```

Os valores 88, 91 e 84 atingem o limite; são três elementos, cuja soma é 263. A soma incorpora esses números inteiros, não apenas suas diferenças em relação a 80. As chaves permitem distinguir contagem e total sem depender da posição de cada resposta.

<a id="sol-ch05-13"></a>

## Solução do Exercício 13

Uma possibilidade é separar classificação individual, contagem de dias abaixo da meta, produção acumulada e produção excedente. Essas operações respondem a perguntas diferentes e podem entregar valores para um relatório comum. O relatório pode então reutilizar as respostas sem recalcular suas regras.

| Operação             | Entradas                  | Resultado                   |
|----------------------|---------------------------|-----------------------------|
| Classificar produção | Uma produção e a meta     | Abaixo, exata ou acima      |
| Contar dias abaixo   | Lista de produções e meta | Quantidade de dias          |
| Acumular produção    | Lista de produções        | Total de unidades           |
| Acumular excedente   | Lista de produções e meta | Soma das parcelas positivas |

Nas resoluções seguintes, usaremos `classificar_producao`, `contar_dias_abaixo_meta`, `calcular_producao_acumulada` e `calcular_producao_excedente`. Esses nomes e essa divisão são uma escolha válida, não a única. Uma alternativa deve explicitar entradas e saídas e evitar repetir desnecessariamente as mesmas regras.

## Solução do Exercício 14

Primeiro verificamos se a produção é menor que a meta. Se não for, verificamos a igualdade; o caso restante é acima da meta. Cada ramo devolve uma classificação. O laço externo fornece uma observação de cada vez à mesma função.

``` python
producao_diaria = [480, 520, 505, 450, 540, 510]
meta_diaria = 500

def classificar_producao(producao, meta):
    if producao < meta:
        return "Abaixo da meta"
    elif producao == meta:
        return "Meta exata"
    else:
        return "Acima da meta"

for producao in producao_diaria:
    print(f"{producao}: {classificar_producao(producao, meta_diaria)}")
```

``` text
480: Abaixo da meta
520: Acima da meta
505: Acima da meta
450: Abaixo da meta
540: Acima da meta
510: Acima da meta
```

As produções 480 e 450 ficam abaixo; 520, 505, 540 e 510 ficam acima. Não há observação igual a 500, mas a regra conserva a categoria “Meta exata”. A ausência dessa categoria na saída decorre dos dados, não da falta de um caminho para tratá-la.

<a id="sol-ch05-15"></a>

## Solução do Exercício 15

O contador é local e começa em zero em cada chamada. O teste `producao < meta` seleciona os dias de interesse. Somamos uma ocorrência para cada dia selecionado e retornamos a quantidade depois de examinar toda a lista.

``` python
def contar_dias_abaixo_meta(producoes, meta):
    contador = 0
    for producao in producoes:
        if producao < meta:
            contador = contador + 1
    return contador

dias_abaixo = contar_dias_abaixo_meta(producao_diaria, meta_diaria)
print(dias_abaixo)
```

``` text
2
```

O retorno é 2: dois dos seis dias ficaram abaixo de 500 unidades. O indicador não mede a soma das faltas de produção. Armazená-lo em `dias_abaixo` permite usá-lo no relatório sem repetir a função de contagem dentro da impressão.

<a id="sol-ch05-16"></a>

## Solução do Exercício 16

Esta operação incorpora todos os dias, sem selecionar apenas os que atingiram a meta. O acumulador começa em zero, recebe cada produção e é devolvido após o laço. A comparação com `sum` usa exatamente a mesma lista.

``` python
def calcular_producao_acumulada(producoes):
    total = 0
    for producao in producoes:
        total = total + producao
    return total

producao_acumulada = calcular_producao_acumulada(producao_diaria)
print(producao_acumulada)
print(sum(producao_diaria))
```

``` text
3005
3005
```

Ambos os métodos produzem 3005 unidades. Esse é o total do período observado, não a produção média diária. A concordância entre os métodos confirma a soma para esses dados; a versão manual deixa visível o procedimento de acumulação.

<a id="sol-ch05-17"></a>

## Solução do Exercício 17

A assinatura recebe a lista e a meta, para que o corpo não dependa do número 500 fixado dentro da função. O teste seleciona produções maiores que a meta. Para cada uma, calculamos `producao - meta` e somamos apenas essa diferença ao acumulador.

``` python
def calcular_producao_excedente(producoes, meta):
    excedente_total = 0
    for producao in producoes:
        if producao > meta:
            excedente = producao - meta
            excedente_total = excedente_total + excedente
    return excedente_total

producao_excedente = calcular_producao_excedente(producao_diaria, meta_diaria)
print(producao_excedente)
```

``` text
75
```

As parcelas são 20, 5, 40 e 10, totalizando 75 unidades. Os dias abaixo da meta não descontam esse indicador. O saldo de toda a produção frente à meta acumulada seria outra medida: 3005 − 6 × 500 = 5. Também não somamos integralmente as produções dos dias acima, como faríamos na seleção do Exercício 12. A regra verbal determina qual parcela entra na soma.

## Solução do Exercício 18

O relatório depende das definições e dos retornos dos itens anteriores. Reaplicamos a função de classificação aos seis valores e usamos os indicadores já guardados. `len` informa o número de dias; `\n` nas mensagens separa visualmente os blocos do relatório.

``` python
print("Controle de Produção Orion")
print("\nClassificações:")
for producao in producao_diaria:
    classificacao = classificar_producao(producao, meta_diaria)
    print(f"{producao}: {classificacao}")

print(f"\nDias observados: {len(producao_diaria)}")
print(f"Dias abaixo da meta: {dias_abaixo}")
print(f"Produção acumulada: {producao_acumulada} unidades")
print(f"Produção excedente: {producao_excedente} unidades")
```

``` text
Controle de Produção Orion

Classificações:
480: Abaixo da meta
520: Acima da meta
505: Acima da meta
450: Abaixo da meta
540: Acima da meta
510: Acima da meta

Dias observados: 6
Dias abaixo da meta: 2
Produção acumulada: 3005 unidades
Produção excedente: 75 unidades
```

Uma conclusão possível, em quatro frases: “Nos seis dias observados, duas produções ficaram abaixo da meta e quatro ficaram acima, sem ocorrência de meta exata. A produção acumulada foi de 3.005 unidades. As parcelas excedentes dos dias acima da meta somaram 75 unidades, sem descontar os dias abaixo. Esses resultados descrevem os dados didáticos e não explicam as causas das diferenças entre os dias.”

A interpretação acompanha as regras efetivamente programadas. Quantidade de dias, total produzido e excedente são indicadores distintos; apresentar um deles não substitui os demais.
