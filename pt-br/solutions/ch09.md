## Preparação do Bloco A

Importamos pandas e construímos a base do bloco. Cada lista fornece uma coluna; valores na mesma posição formam a mesma observação. Os dados e suas unidades foram definidos na preparação do suplemento.

``` python
import pandas as pd
df_pedidos = pd.DataFrame(
    {
        'pedido': ['P1', 'P2', 'P3', 'P4', 'P5', 'P6'],
        'receita': [120, None, 95, 140, None, 110],
        'desconto': [0.05, None, 0.0, 0.1, None, 0.03],
        'canal': ['Loja', 'Online', 'Loja', 'Online', None, 'Loja']
    }
)
print(df_pedidos)
```

``` text

0     P1    120.0      0.05    Loja
1     P2      NaN       NaN  Online
2     P3     95.0      0.00    Loja

4     P5      NaN       NaN     NaN
5     P6    110.0      0.03    Loja
```

<a id="sol-ch09-01"></a>

## Solução do Exercício 01

A pergunta é onde falta informação, não qual valor deveria ocupar cada posição. Aplicamos `isna()` ao DataFrame inteiro e imprimimos a máscara. A forma da tabela é preservada, permitindo relacionar cada Booleano à linha e à coluna correspondentes.

``` python
print(df_pedidos.isna())
```

``` text
   pedido  receita  desconto  canal
0   False    False     False  False
1   False     True      True  False
2   False    False     False  False
3   False    False     False  False
4   False     True      True   True
5   False    False     False  False
```

P2 e P5 têm receita e desconto ausentes; P5 também não informa canal. `True` localiza ausência, sem decidir tratamento. Desconto zero em P3 é um valor conhecido e aparece como `False` nessa verificação.

<a id="sol-ch09-02"></a>

## Solução do Exercício 02

Retomamos a máscara de ausência e somamos suas linhas por coluna. Cada `True` contribui com um. O resultado é uma Series: seus rótulos são os nomes das colunas e seus valores são as contagens.

``` python
print(df_pedidos.isna().sum())
```

``` text
pedido      0
receita     2
desconto    2
canal       1
dtype: int64
```

Pedido tem zero ausências; receita e desconto têm duas cada; canal tem uma. Somar essas contagens produziria cinco células ausentes, não cinco pedidos diferentes.

<a id="sol-ch09-03"></a>

## Solução do Exercício 03

A média de uma máscara booleana divide o número de ausências pela quantidade de linhas. Multiplicamos por 100 para obter percentuais. Aqui o denominador é seis em todas as colunas, pois examinamos a base completa.

``` python
print(df_pedidos.isna().mean() * 100)
```

``` text
pedido       0.000000
receita     33.333333
desconto    33.333333
canal       16.666667
dtype: float64
```

Receita e desconto têm 33,33% de ausência; canal, 16,67%. Os percentuais dimensionam o problema. Eles não demonstram que preencher ou excluir será adequado, nem fornecem um limite universal de qualidade.

<a id="sol-ch09-04"></a>

## Solução do Exercício 04

`notna()` devolve `True` onde a receita está disponível. Usamos essa máscara dentro dos colchetes de `df_pedidos`, preservando todas as colunas das linhas selecionadas. Nenhuma atribuição modifica a base original.

``` python
print(df_pedidos[df_pedidos['receita'].notna()])
```

``` text
  pedido  receita  desconto   canal
0     P1    120.0      0.05    Loja
2     P3     95.0      0.00    Loja
3     P4    140.0      0.10  Online
5     P6    110.0      0.03    Loja
```

P1, P3, P4 e P6 possuem receita registrada. A seleção mantém os índices 0, 2, 3 e 5. O critério verifica disponibilidade, sem certificar todos os campos dos pedidos.

<a id="sol-ch09-05"></a>

## Solução do Exercício 05

`subset` limita a decisão de exclusão à receita. Guardamos o retorno de `dropna()` em `relatorio` e imprimimos as formas da base e do recorte. Assim distinguimos uma versão de análise da informação original.

``` python
relatorio = df_pedidos.dropna(subset=['receita'])
print('Antes/depois:', df_pedidos.shape, relatorio.shape)
```

``` text
Antes/depois: (6, 4) (4, 4)
```

A base continua com seis linhas e quatro colunas; o relatório tem quatro linhas e quatro colunas. P2 e P5 foram retirados apenas desse relatório. Os exercícios seguintes que pedem a base completa devem retomar `df_pedidos`.

## Solução do Exercício 06

A regra define que desconto ausente significa zero. Criamos uma cópia da base completa, aplicamos `fillna(0)` apenas à coluna desconto e atribuímos o retorno à mesma coluna. A seleção final permite conferir cada pedido e seu desconto.

``` python
df_trabalho = df_pedidos.copy()
df_trabalho['desconto'] = df_trabalho['desconto'].fillna(0)
print(df_trabalho[['pedido', 'desconto']])
```

``` text
  pedido  desconto
0     P1      0.05
1     P2      0.00
2     P3      0.00
3     P4      0.10
4     P5      0.00
5     P6      0.03
```

P2 e P5 passam a ter desconto zero; os descontos conhecidos são preservados. As seis linhas permanecem na cópia. Receita e canal não foram preenchidos, pois nenhuma regra forneceu seus valores corretos.

``` python
m = df_fornecedores.duplicated()
```

Somente o índice 3, segunda ocorrência completa de F3, recebe `True`. A contagem é um. A regra da preparação confirma que o cadastro deveria ser único e que essa repetição é indevida.

## Solução do Exercício 09

Como o diagnóstico e o contexto confirmaram o erro, guardamos `drop_duplicates()` em `df_unico`. `shape` permite comparar linhas e colunas ao mesmo tempo; o primeiro número de cada par é a contagem de registros.

``` python
df_unico = df_fornecedores.drop_duplicates()

```

``` text
Antes/depois: (6, 3) (5, 3)
```

A forma muda de `(6, 3)` para `(5, 3)`. A primeira ocorrência F3 permanece; os índices são 0, 1, 2, 4 e 5. Use `df_unico` nas próximas inspeções de categorias, sem sobrescrever `df_fornecedores`.

## Solução do Exercício 10

Selecionamos a coluna categoria da versão sem duplicata e chamamos `unique()`. O retorno mostra valores distintos na ordem de aparecimento. A inspeção precede a escolha das representações que podem ser padronizadas.

``` python
print(df_unico['categoria'].unique())
```

``` text
<StringArray>
['Insumo', ' insumo ', 'EQUIPAMENTO', 'Peça Técnica', 'peça-técnica']
Length: 5, dtype: str
```

Existem cinco grafias. `Insumo` e `' insumo '` diferem por espaços e capitalização; `Peça Técnica` e `peça-técnica` também diferem pelo hífen. Essas diferenças serão tratadas em etapas, preservando a categoria substantiva.

<a id="sol-ch09-11"></a>

## Solução do Exercício 11

`str.strip()` atua nos espaços iniciais e finais de cada texto. Guardamos a Series resultante em `categoria_strip`, sem modificar a tabela. A consulta de valores únicos permite verificar exatamente o que mudou.

``` python
categoria_strip = df_unico['categoria'].str.strip()

```

``` text
<StringArray>
['Insumo', 'insumo', 'EQUIPAMENTO', 'Peça Técnica', 'peça-técnica']
Length: 5, dtype: str
```

`' insumo '` tornou-se `insumo`, sem os espaços externos. As letras continuam minúsculas; não houve mudança de significado para outra categoria. A diferença de capitalização em relação a `Insumo` será tratada no próximo exercício.

## Solução do Exercício 12

Usamos a Series sem espaços produzida no Exercício 11. `str.title()` padroniza a capitalização e seu resultado é guardado em `categoria_title`. Essa dependência evita voltar às grafias com espaços.

``` python
categoria_title = categoria_strip.str.title()

```

``` text
<StringArray>
['Insumo', 'Equipamento', 'Peça Técnica', 'Peça-Técnica']
Length: 4, dtype: str
```

Restam quatro grafias: Insumo, Equipamento, Peça Técnica e Peça-Técnica. As duas primeiras estão uniformes. A diferença entre espaço interno e hífen continua presente e exige a regra cadastral do próximo item.

<a id="sol-ch09-13"></a>

## Solução do Exercício 13

O padrão deste cadastro usa `Peça-Técnica`. Aplicamos `replace()` à Series capitalizada do Exercício 12, com um dicionário que associa a grafia sem hífen à grafia desejada. Essa regra não elimina ou reorganiza fornecedores.

``` python
categoria_final = categoria_title.replace({'Peça Técnica': 'Peça-Técnica'})
print(categoria_final.unique())
```

``` text
<StringArray>
['Insumo', 'Equipamento', 'Peça-Técnica']
Length: 3, dtype: str
```

Restam três categorias substantivas: Insumo, Equipamento e Peça-Técnica. O hífen é uma convenção explícita deste cadastro. Não devemos aplicar o mesmo padrão a qualquer vocabulário sem verificar seu significado.

## Solução do Exercício 14

Recomeçamos de `df_fornecedores`, removemos a repetição confirmada e copiamos o resultado. Guardamos as categorias anteriores à padronização. Retiramos os espaços externos em uma Series intermediária. Depois atribuímos a capitalização e a recodificação à coluna da cópia. Por fim, comparamos a contagem de duplicatas com a base original e inspecionamos as categorias antes e depois.

``` python
df_limpo = df_fornecedores.drop_duplicates().copy()
antes = df_limpo['categoria'].unique()
categoria = df_limpo['categoria'].str.strip()
df_limpo['categoria'] = categoria.str.title()
df_limpo['categoria'] = (
    df_limpo['categoria'].replace({'Peça Técnica': 'Peça-Técnica'})
)
print('Duplicatas antes/depois:', df_fornecedores.duplicated().sum(), df_limpo.duplicated().sum())
print('Categorias antes:', antes)
print('Categorias depois:', df_limpo['categoria'].unique())
```

``` text

['Insumo', ' insumo ', 'EQUIPAMENTO', 'Peça Técnica', 'peça-técnica']
Length: 5, dtype: str
Categorias depois: <StringArray>
['Insumo', 'Equipamento', 'Peça-Técnica']
Length: 3, dtype: str
```

A repetição excedente caiu de um para zero; a cópia tem cinco registros. As cinco grafias encontradas após a deduplicação convergem para três categorias. A variável `antes` guarda categorias antes da padronização textual, não uma segunda cópia da tabela inteira. A base original permanece disponível.

## Solução do Exercício 16

``` python
print('Pode tratar: duplicata U3, desconto ausente e grafia de setor.')
```


Podemos tratar duplicata, desconto e grafias, e converter a quantidade porque todos os textos representam inteiros. Custo de U5, setor de U6 e quantidade correta de U7 exigem consulta à fonte. Não há regra para recodificar status A/I; esses códigos permanecem como fornecidos.

Duplicatas e ausências de desconto são zero; há três setores conhecidos e uma ausência; quantidade é inteira; uma violação de domínio permanece. Essa é uma validação coerente com as ações possíveis, não uma certificação de que toda a informação está correta.


Atlas termina com seis linhas e duas células ausentes: custo de U5 e setor de U6. A quantidade inválida de U7 é outra pendência, não uma dessas ausências. Duplicação, desconto, grafias e tipo foram tratados; os três problemas remanescentes precisam de fonte. A base melhorou sem que informação desconhecida fosse fabricada.
