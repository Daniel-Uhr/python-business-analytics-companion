## Solução do Exercício 01

A resposta começa pelo significado da linha. Se cada linha descreve um pedido, o identificador precisa distinguir pedidos, mesmo que vários pertençam ao mesmo cliente ou à mesma região.

A unidade é um pedido, e `pedido_id` é a chave candidata que deve identificá-lo. O nome da coluna sugere sua função; a unicidade e o preenchimento precisam ser verificados nos dados. A construção concreta aparece na próxima resolução.

<a id="sol-ch11-02"></a>

## Solução do Exercício 02

Esta é uma construção aberta. Uma resposta possível usa N1 e N2 no Norte, S1 e S2 no Sul e os valores abaixo em reais. Cada dicionário descreve as colunas; listas na mesma posição formam um pedido. Mantemos nomes e significados compatíveis nas duas bases.

``` python
pedidos_norte = pd.DataFrame(
    {
        'pedido_id': ['N1', 'N2'],
        'regiao': ['Norte', 'Norte'],
        'valor': [1200, 900]
    }
)
pedidos_sul = pd.DataFrame(
    {
        'pedido_id': ['S1', 'S2'],
        'regiao': ['Sul', 'Sul'],
        'valor': [1500, 1100]
    }
)
print(pedidos_norte)
print(pedidos_sul)
```

``` text
  pedido_id regiao  valor
0        N1  Norte   1200
1        N2  Norte    900
  pedido_id regiao  valor
0        S1    Sul   1500
1        S2    Sul   1100
```

Há dois pedidos em cada região e quatro IDs distintos. Outros valores também atendem ao enunciado, desde que respeitem essas condições. Os próximos resultados numéricos correspondem a este exemplo de resposta.

<a id="sol-ch11-03"></a>

## Solução do Exercício 03

Precisamos reunir pedidos, sem acrescentar atributos de outra entidade. `pd.concat` recebe as duas bases em uma lista; `ignore_index=True` cria o índice sequencial do resultado. O código também guarda a contagem esperada, que será interpretada no Exercício 04.

``` python
pedidos = pd.concat([pedidos_norte, pedidos_sul], ignore_index=True)
esperadas = len(pedidos_norte) + len(pedidos_sul)
print(pedidos)
print('Esperadas:', esperadas)
print('Obtidas:', len(pedidos))
```

``` text
  pedido_id regiao  valor
0        N1  Norte   1200
1        N2  Norte    900
2        S1    Sul   1500
3        S2    Sul   1100
Esperadas: 4
Obtidas: 4
```

A base `pedidos` mantém os quatro registros e suas associações entre ID, região e valor. A primeira fonte aparece antes da segunda. Renumerar o índice não modifica os códigos de pedido.

<a id="sol-ch11-04"></a>

## Solução do Exercício 04

Usamos a contagem apresentada na resolução anterior: `len(pedidos_norte) + len(pedidos_sul)` soma as duas origens, enquanto `len(pedidos)` mede o resultado. Não precisamos executar novamente a concatenação para explicar essa comparação.

Esperávamos 2 + 2 = 4 linhas e obtivemos 4. Esse resultado confirma a contagem, mas não verifica sozinho a unicidade dos IDs ou a compatibilidade das unidades monetárias. Essas são condições diferentes.

<a id="sol-ch11-05"></a>

## Solução do Exercício 05

Selecionamos `pedido_id`, marcamos suas ocorrências repetidas com `duplicated()` e somamos os marcadores. A verificação deve ser feita no resultado conjunto, pois IDs distintos dentro de cada origem ainda poderiam se repetir entre origens.

``` python
duplicados = pedidos['pedido_id'].duplicated().sum()
print('IDs duplicados:', duplicados)
```

``` text
IDs duplicados: 0
```

O resultado zero indica que nenhum pedido aparece depois de uma ocorrência anterior do mesmo ID. Isso é compatível com os quatro códigos fornecidos. Não é uma checagem geral de integridade dos atributos.

<a id="sol-ch11-06"></a>

## Solução do Exercício 06

A base combinada permite resumir os pedidos das duas origens. `groupby("regiao")` define os grupos, a seleção de `valor` define a medida e `sum()` a agrega. A unidade do resultado passa a ser uma região.

``` python
valor_regiao = pedidos.groupby('regiao')['valor'].sum()
print(valor_regiao)
```

``` text
regiao
Norte    2100
Sul      2600
Name: valor, dtype: int64
```

Neste exemplo, Norte soma R\$ 2.100 e Sul, R\$ 2.600. A afirmação descreve os quatro pedidos escolhidos, sem período informado. Se você construiu outra base válida no Exercício 02, seus totais podem ser diferentes; a interpretação deve acompanhar seus próprios dados.

## Solução do Exercício 07

A Base Alfa tem uma linha por pedido; a Base Beta tem uma linha por cliente. As colunas também desempenham papéis diferentes. Empilhar registros dessas entidades misturaria unidades em uma mesma tabela.

A concatenação vertical não é adequada para enriquecer os pedidos. O pandas conseguir executar uma operação não prova que ela faça sentido. Para acrescentar cliente e segmento, a ligação apropriada é por `cliente_id`, verificando a unicidade do cadastro. Não é necessário inventar código ou dados adicionais para justificar a escolha.

## Solução do Exercício 08

Pedidos é a tabela principal, com uma linha por pedido. Clientes descreve uma linha por cliente. A chave de ligação é `cliente_id`, que pode se repetir nos pedidos. Uma resposta possível é a construção abaixo; C9 aparece em um pedido, mas não no cadastro.

``` python
pedidos = pd.DataFrame(
    {
        'pedido_id': ['P1', 'P2', 'P3', 'P4'],
        'cliente_id': ['C1', 'C2', 'C1', 'C9'],
        'valor': [800, 1200, 600, 500]
    }
)
clientes = pd.DataFrame(
    {
        'cliente_id': ['C1', 'C2'],
        'cliente': ['Alfa', 'Beta'],
        'segmento': ['Empresarial', 'Varejo']
    }
)
print(pedidos)
print(clientes)
```

``` text
  pedido_id cliente_id  valor
0        P1         C1    800
1        P2         C2   1200
2        P3         C1    600
3        P4         C9    500
  cliente_id cliente     segmento
0         C1    Alfa  Empresarial
1         C2    Beta       Varejo
```

C1 aparece em P1 e P3, enquanto o cadastro contém apenas uma descrição de C1. P4 aponta para C9, permitindo investigar uma falta de correspondência sem deixar a chave do pedido vazia. Os valores em reais são uma escolha ilustrativa, não uma exigência do enunciado.

<a id="sol-ch11-09"></a>

## Solução do Exercício 09

Chamamos `merge` em `pedidos`, fornecendo `clientes` à direita. `on` informa o código compartilhado e `left` mantém os pedidos, inclusive aquele sem cadastro. A impressão da tabela e das contagens permite examinar atributos e quantidade de linhas.

``` python
pedidos_clientes = pedidos.merge(clientes, on='cliente_id', how='left')
print(pedidos_clientes)
print(
    'Antes:',
    len(pedidos),
    'Depois:',
    len(pedidos_clientes)
)
```

``` text
  pedido_id cliente_id  valor cliente     segmento
0        P1         C1    800    Alfa  Empresarial
1        P2         C2   1200    Beta       Varejo
2        P3         C1    600    Alfa  Empresarial
3        P4         C9    500     NaN          NaN
Antes: 4 Depois: 4
```

Os atributos de Alfa e Beta foram associados aos pedidos correspondentes. P4 permanece com seus R\$ 500 e atributos de cliente ausentes. Não completamos segmento ou nome por suposição.

<a id="sol-ch11-10"></a>

## Solução do Exercício 10

A saída da resolução anterior mostra quatro linhas antes e quatro depois. A justificativa é a unicidade de `cliente_id` no cadastro: cada pedido encontra no máximo uma linha de cliente.

C1 se repete nos pedidos, o que é permitido; não se repete no cadastro. O pedido de C9 também permanece, mesmo sem par. Se houvesse mais de uma correspondência à direita, `left` poderia aumentar a quantidade de linhas.

<a id="sol-ch11-11"></a>

## Solução do Exercício 11

Refazemos a junção com um indicador explícito. A comparação de `_merge` com `left_only` seleciona registros que vieram somente de pedidos. Essa escolha investiga a correspondência, sem depender de interpretar visualmente nomes vazios.

``` python
diagnostico = pedidos.merge(
    clientes,
    on='cliente_id',
    how='left',
    indicator=True
)
print(diagnostico[diagnostico['_merge'] == 'left_only'])
```

``` text
  pedido_id cliente_id  valor cliente segmento     _merge
3        P4         C9    500     NaN      NaN  left_only
```

A linha selecionada é P4, ligada a C9, com valor de R\$ 500. Seu cadastro não está disponível nesta base. O diagnóstico não identifica por que ele falta nem autoriza atribuir uma categoria.

<a id="sol-ch11-12"></a>

## Solução do Exercício 12

Muitos pedidos podem apontar para um único cliente cadastrado: a relação é muitos-para-um. Depois de justificar essa expectativa, podemos verificar a chave direita com `validate="many_to_one"`. O código abaixo acrescenta essa checagem à junção.

``` python
pedidos_clientes_validados = pedidos.merge(
    clientes,
    on='cliente_id',
    how='left',
    validate='many_to_one'
)
print('Linhas validadas:', len(pedidos_clientes_validados))
```

``` text
Linhas validadas: 4
```

A operação preserva as quatro linhas e aceita a estrutura do cadastro. C9 continua ausente: `validate` verifica cardinalidade, não preenche o cadastro e não garante correspondência para todos os pedidos.

## Solução do Exercício 13

Somente agora acrescentamos a coluna de produto à base original de pedidos. Nesta resposta possível, R1 e R2 são associados aos quatro pedidos na ordem mostrada. As listas precisam ter o mesmo comprimento da base. A integração é refeita desde `pedidos`: o DataFrame integrado anteriormente não recebe a nova coluna de forma automática.

``` python
pedidos['produto_id'] = ['R1', 'R2', 'R2', 'R1']
produtos = pd.DataFrame(
    {
        'produto_id': ['R1', 'R2'],
        'produto': ['Roteador', 'Terminal'],
        'categoria': ['Rede', 'Operação']
    }
)
pedidos_clientes_produtos = pedidos.merge(
    clientes,
    on='cliente_id',
    how='left',
    validate='many_to_one'
).merge(
    produtos,
    on='produto_id',
    how='left',
    validate='many_to_one'
)
print(pedidos_clientes_produtos)
print('Pedidos antes:', len(pedidos))
print('Linhas integradas:', len(pedidos_clientes_produtos))
print(
    'Clientes ausentes:',
    pedidos_clientes_produtos['cliente'].isna().sum()
)
print(
    'Produtos ausentes:',
    pedidos_clientes_produtos['produto'].isna().sum()
)
```

``` text
  pedido_id cliente_id  valor produto_id cliente     segmento
0        P1         C1    800         R1    Alfa  Empresarial
1        P2         C2   1200         R2    Beta       Varejo
2        P3         C1    600         R2    Alfa  Empresarial
3        P4         C9    500         R1     NaN          NaN

    produto categoria
0  Roteador      Rede
1  Terminal  Operação
2  Terminal  Operação
3  Roteador      Rede
Pedidos antes: 4
Linhas integradas: 4
Clientes ausentes: 1

```

As duas junções usam cadastros únicos e preservam quatro pedidos. Todos os produtos têm correspondência; P4/C9 continua sem cliente. A ausência em uma relação não implica ausência na outra. Outros catálogos coerentes com seu enunciado também são válidos.

## Solução do Exercício 20

O relatório escolhido tem fornecedores nas linhas, grupos de material nas colunas e valor de pedidos nas células. `aggfunc="sum"` declara a regra de totalização. Nesta amostra, cada combinação observada de fornecedor conhecido e grupo aparece uma vez; `pivot()` também poderia reorganizá-la. `pivot_table()` continua apropriado para expressar o relatório de totais e permitir a soma quando houver mais de um pedido por combinação. Não há repetição a inventar nos dados atuais.

``` python
tabela_nexo = fornecedores_conhecidos.pivot_table(
    index='fornecedor',
    columns='grupo_material',
    values='valor',
    aggfunc='sum',
    fill_value=0
)
print(tabela_nexo)
print('Total geral:', valor_total_pedidos)
print(
    'Total com fornecedor conhecido:',
    valor_fornecedores_conhecidos
)
print('Valor sem correspondência:', valor_sem_correspondencia)
print('Total reorganizado:', tabela_nexo.to_numpy().sum())
```

``` text
grupo_material  Automação  Componente  Estrutural
fornecedor                                       
Aço Forte            3200           0        2400
Logis                2100        1800           0
Tecnosul                0           0        1500
Total geral: 11900
Total com fornecedor conhecido: 11000
Valor sem correspondência: 900
Total reorganizado: 11000
```

O quadro soma R\$ 11.000 e cobre apenas fornecedores conhecidos. Os R\$ 900 de N6 continuam separados e reconciliados com o total geral de R\$ 11.900. Zeros indicam combinações sem valor observado entre as categorias deste relatório; não significam que F9 tenha sido identificado ou que seu valor seja zero.
