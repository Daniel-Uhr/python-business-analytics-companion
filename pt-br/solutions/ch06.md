## Solução do Exercício 01

Precisamos disponibilizar a biblioteca antes de criar o objeto. `import numpy as np` estabelece o nome curto usado para chamar `np.array()`. A lista entre colchetes fornece os quatro valores, e a atribuição guarda o array em `custos`.

``` python
import numpy as np

custos = np.array([75, 82, 79, 91])
print(custos)
```

``` text
[75 82 79 91]
```

A saída confirma quatro custos na ordem fornecida. Cada número está em milhares de reais: 75 representa R\$ 75 mil. A unidade não fica armazenada automaticamente no array; ela pertence à definição do problema e precisa acompanhar a interpretação.

<a id="sol-ch06-02"></a>

## Solução do Exercício 02

Cada atributo responde a uma pergunta. A forma descreve a quantidade de posições por dimensão; `ndim` conta dimensões; `size` conta elementos; `dtype` identifica o tipo de armazenamento. Consultamos os atributos com um ponto, sem parênteses depois de seus nomes.

``` python
print("Shape:", custos.shape)
print("Dimensões:", custos.ndim)
print("Elementos:", custos.size)
print("Tipo:", custos.dtype)
```

``` text
Shape: (4,)
Dimensões: 1
Elementos: 4
Tipo: int64
```

`(4,)` indica uma única dimensão com quatro posições; não é uma tabela de uma linha e quatro colunas. `ndim` vale 1 e `size` vale 4. Neste ambiente, o tipo é `int64`; a saída histórica das notas era `int32`. Ambos representam inteiros, e essa diferença prevista não modifica os custos nem o critério do exercício.

<a id="sol-ch06-03"></a>

## Solução do Exercício 03

O primeiro elemento usa índice 0; o último pode ser acessado com -1. Como os índices começam em zero, o segundo custo está na posição 1. A instrução de atribuição modifica essa posição do array já existente.

``` python
print("Primeiro:", custos[0])
print("Último:", custos[-1])

custos[1] = 84
print("Atualizado:", custos)
```

``` text
Primeiro: 75
Último: 91
Atualizado: [75 84 79 91]
```

Os valores consultados são 75 e 91 mil reais. Depois da atribuição, o array passa a ser `[75, 84, 79, 91]`: apenas o segundo custo mudou, de 82 para 84 mil. Essa é uma alteração dos dados do exemplo, distinta de simplesmente exibir uma posição.

<a id="sol-ch06-04"></a>

## Solução do Exercício 04

O corte `[:2]` começa na primeira posição e para antes do índice 2. O corte `[2:]` começa justamente nesse índice e segue até o fim. Os cortes são aplicados ao estado atual de `custos`, que conserva o valor 84 do exercício anterior.

``` python
print("Primeiros dois:", custos[:2])
print("A partir do terceiro:", custos[2:])
```

``` text
Primeiros dois: [75 84]
A partir do terceiro: [79 91]
```

Os grupos são `[75, 84]` e `[79, 91]`, em milhares de reais. Uma saída com 82 no primeiro grupo indicaria que a atualização anterior não foi mantida. Esses comandos apenas selecionam e exibem os valores; não alteram o array.

<a id="sol-ch06-05"></a>

## Solução do Exercício 05

Recriamos a base indicada no enunciado. Multiplicar por 1,08 conserva 100% do valor e acrescenta 8%; somar 5 acrescenta uma quantia fixa na escala de milhares. Os dois resultados recebem nomes próprios. O segundo cálculo usa a base, não o resultado do primeiro cenário.

``` python
custos_base = np.array([75, 82, 79, 91])

custos_aumento = custos_base * 1.08
custos_acrescimo = custos_base + 5

print("Aumento de 8%:", custos_aumento)
print("Acréscimo de 5:", custos_acrescimo)
print("Original:", custos_base)
```

``` text
Aumento de 8%: [81.   88.56 85.32 98.28]
Acréscimo de 5: [80 87 84 96]
Original: [75 82 79 91]
```

No cenário proporcional, os custos são 81; 88,56; 85,32; e 98,28 mil reais. No cenário fixo, são 80, 87, 84 e 96 mil. A última impressão confirma a base original. Broadcasting aplica cada escalar a todas as posições; não transforma esses cenários em previsões de custos futuros.

<a id="sol-ch06-06"></a>

## Solução do Exercício 06

Criamos as duas estruturas com os mesmos valores para isolar a diferença de significado do operador. O código mantém os nomes separados e exibe os resultados; não estamos comparando tempos de execução.

``` python
valores_lista = [12, 18, 25]
valores_array = np.array([12, 18, 25])

print("Lista:", valores_lista * 2)
print("Array:", valores_array * 2)
```

``` text
Lista: [12, 18, 25, 12, 18, 25]
Array: [24 36 50]
```

A lista é repetida e passa a ter seis elementos. O array continua com três elementos, agora 24, 36 e 50, porque cada valor foi multiplicado. Para expressar esse cálculo numérico, o array é mais direto. Isso não torna listas inadequadas para outras tarefas nem estabelece uma vantagem de desempenho medida.

<a id="sol-ch06-07"></a>

## Solução do Exercício 07

A condição é estrita: “maiores que” corresponde a `>`, e não a `>=`. Ao comparar o array com 50, NumPy aplica o critério a cada posição e devolve um booleano por tempo.

``` python
import numpy as np

tempos = np.array([42, 55, 38, 61, 47, 70])
print(tempos > 50)
```

``` text
[False  True False  True False  True]
```

As posições verdadeiras correspondem a 55, 61 e 70 minutos. O resultado ainda é um array de condições, com seis posições; ele não é o subconjunto de três tempos. Um valor exatamente igual a 50 não atenderia à condição, embora não apareça nesses dados.

<a id="sol-ch06-08"></a>

## Solução do Exercício 08

A comparação é a mesma, mas agora seu resultado recebe um nome. Essa atribuição permite reutilizar a condição na seleção seguinte e torna explícito o papel do array booleano.

``` python
mascara_atraso = tempos > 50
print(mascara_atraso)
```

``` text
[False  True False  True False  True]
```

Há seis booleanos, um por observação. `True` significa que o tempo correspondente supera 50 minutos; não representa a duração do atendimento. O nome da máscara comunica o critério adotado neste exercício.

<a id="sol-ch06-09"></a>

## Solução do Exercício 09

Colocamos a máscara entre os colchetes do array de tempos. NumPy conserva os valores cujas posições são verdadeiras e guarda o resultado em `tempos_atraso`. A condição e os valores selecionados são objetos com funções diferentes.

``` python
tempos_atraso = tempos[mascara_atraso]
print(tempos_atraso)
```

``` text
[55 61 70]
```

A seleção contém 55, 61 e 70 minutos, nessa ordem. O array original tem seis elementos; o subconjunto tem três. A seleção não é uma soma, uma média ou uma ordenação: ela apenas conserva as observações que atendem ao critério.

<a id="sol-ch06-10"></a>

## Solução do Exercício 10

Aplicamos os métodos a `tempos`, não ao subconjunto `tempos_atraso`. Assim, os quatro indicadores se referem às seis observações. A média usa a soma de todos os valores dividida por seis.

``` python
print("Total:", tempos.sum())
print("Média:", tempos.mean())
print("Mínimo:", tempos.min())
print("Máximo:", tempos.max())
```

``` text
Total: 313
Média: 52.166666666666664
Mínimo: 38
Máximo: 70
```

O total é 313 minutos, a média é aproximadamente 52,17 minutos por observação e os extremos são 38 e 70 minutos. A longa representação decimal da média vem do cálculo com ponto flutuante; a interpretação arredondada não altera os dados. Não confunda essa média geral com a média apenas dos tempos acima de 50.

<a id="sol-ch06-11"></a>

## Solução do Exercício 11

Reconstruímos as três etapas para tornar visível o raciocínio. `tempos > 50` produz a condição; `tempos[mascara_atraso]` forma o subconjunto; `size` conta seus elementos, e `mean()` calcula sua média. O atributo de tamanho não recebe parênteses, enquanto o método da média recebe.

``` python
mascara_atraso = tempos > 50
tempos_atraso = tempos[mascara_atraso]

quantidade_atraso = tempos_atraso.size
media_atraso = tempos_atraso.mean()

print("Quantidade:", quantidade_atraso)
print(f"Média acima de 50: {media_atraso:.2f} minutos")
```

``` text
Quantidade: 3
Média acima de 50: 62.00 minutos
```

Três observações atendem ao critério, com média de 62 minutos. A especificação `.2f` apenas exibe duas casas decimais. Esse subconjunto é não vazio, por isso a média tem interpretação direta; não devemos atribuir média zero a uma seleção sem observações.

<a id="sol-ch06-12"></a>

## Solução do Exercício 12

“A partir de R\$ 27” inclui o próprio 27, portanto a máscara usa `>=`. Somamos os valores selecionados no numerador e todos os valores informados no denominador. Multiplicar a razão por 100 a expressa como percentual. O denominador é positivo nesses dados.

``` python
custos = np.array([18, 24, 31, 27, 35, 22])
mascara_altos = custos >= 27
custos_altos = custos[mascara_altos]

participacao = custos_altos.sum() / custos.sum() * 100

print("Custos selecionados:", custos_altos)
print(f"Participação: {participacao:.2f}%")
```

``` text
Custos selecionados: [31 27 35]
Participação: 59.24%
```

Os valores selecionados são 31, 27 e 35 reais, cuja soma é 93. A soma dos seis custos unitários é 157, e 93/157 corresponde a aproximadamente 59,24%. O indicador descreve a participação nessa soma, não a participação em gastos totais ponderados por quantidades desconhecidas. Também não é a proporção de observações selecionadas: três entre seis seria 50%, uma pergunta diferente.

<a id="sol-ch06-13"></a>

## Solução do Exercício 13

Cada lista interna fornece a produção de uma linha nos três turnos. A lista externa reúne as quatro linhas de produção. Depois da criação, consultamos os atributos para conferir se a estrutura corresponde à descrição do caso.

``` python
import numpy as np

producao = np.array([
    [480, 510, 495],
    [520, 505, 530],
    [450, 470, 460],
    [550, 545, 560]
])

print("Shape:", producao.shape)
print("Dimensões:", producao.ndim)
print("Elementos:", producao.size)
```

``` text
Shape: (4, 3)
Dimensões: 2
Elementos: 12
```

A forma `(4, 3)` representa quatro linhas de produção e três turnos. `ndim` vale 2, pois os dados têm duas dimensões; `size` vale 12, pois 4 × 3 = 12. Cada observação é uma combinação linha-turno, medida em unidades produzidas. A contagem de dimensões não é a contagem de linhas produtivas.

<a id="sol-ch06-14"></a>

## Solução do Exercício 14

Queremos conservar uma resposta para cada uma das quatro linhas. Para isso, combinamos os três turnos de cada linha, isto é, reduzimos a dimensão das colunas com `axis=1`. A variável de destino identifica o significado dos quatro totais.

``` python
producao_por_linha = producao.sum(axis=1)
print(producao_por_linha)
```

``` text
[1485 1555 1380 1655]
```

As linhas produziram, respectivamente, 1.485, 1.555, 1.380 e 1.655 unidades. O resultado tem quatro elementos, como esperávamos para uma pergunta por linha. Esses totais agregam turnos; não são valores de uma única combinação linha-turno.

<a id="sol-ch06-15"></a>

## Solução do Exercício 15

Agora queremos manter um resultado por coluna, correspondente a cada turno. Para isso, combinamos as quatro linhas de produção com `axis=0`. A mudança do eixo acompanha a mudança da pergunta, sem alterar os dados.

``` python
producao_por_turno = producao.sum(axis=0)
print(producao_por_turno)
```

``` text
[2000 2030 2045]
```

Os totais são 2.000, 2.030 e 2.045 unidades para os três turnos. No Exercício 14, reduzimos turnos para conservar linhas; aqui, reduzimos linhas para conservar turnos. A leitura do formato e dos rótulos do caso é mais segura do que memorizar o eixo como uma palavra isolada.

<a id="sol-ch06-16"></a>

## Solução do Exercício 16

“Abaixo” corresponde a `<`. A comparação preserva a forma 4 × 3 e produz uma condição para cada combinação linha-turno. Ao aplicar a máscara de mesma forma ao array, obtemos uma sequência unidimensional dos valores selecionados. `size` conta os elementos dessa sequência.

``` python
meta = 500
mascara_abaixo = producao < meta
producao_abaixo = producao[mascara_abaixo]

print(mascara_abaixo)
print("Valores abaixo:", producao_abaixo)
print("Quantidade:", producao_abaixo.size)
```

``` text
[[ True False  True]
 [False False False]
 [ True  True  True]
 [False False False]]
Valores abaixo: [480 495 450 470 460]
Quantidade: 5
```

Os valores são 480, 495, 450, 470 e 460 unidades. São cinco observações: duas na Linha 1 e três na Linha 3, identificáveis na máscara. Não são cinco linhas produtivas nem cinco turnos distintos. A seleção segue a ordem das posições verdadeiras; não ordena a produção do menor para o maior valor.

<a id="sol-ch06-17"></a>

## Solução do Exercício 17

O fator 1,03 combina o valor original com o aumento de 3%. A multiplicação aplica esse escalar a cada elemento por broadcasting. Guardar o resultado em `producao_cenario` mantém `producao` disponível como base de comparação.

``` python
producao_cenario = producao * 1.03

print(producao_cenario)
print("Original preservado:")
print(producao)
```

``` text
[[494.4  525.3  509.85]
 [535.6  520.15 545.9 ]
 [463.5  484.1  473.8 ]
 [566.5  561.35 576.8 ]]
Original preservado:
[[480 510 495]
 [520 505 530]
 [450 470 460]
 [550 545 560]]
```

A primeira observação passa de 480 para 494,4 no cenário, e a última, de 560 para 576,8. A segunda impressão confirma que a base permanece intacta. As frações são resultados da hipótese aritmética, não ordens de fabricar frações de produtos. Uma política de arredondamento operacional exigiria informação adicional; não foi inventada aqui. O cenário não prevê a produção futura.

<a id="sol-ch06-18"></a>

## Solução do Exercício 18

Os totais por eixo e a seleção já foram construídos. Calculamos agora a média do subconjunto abaixo da meta e a soma de todas as posições do cenário. O relatório reúne esses objetos; não deve substituir a média do subconjunto pela média geral nem aplicar novamente o fator de 3%.

``` python
media_abaixo = producao_abaixo.mean()
total_cenario = producao_cenario.sum()

print("Controle de Produção Boreal")
print("Totais por linha:", producao_por_linha)
print("Totais por turno:", producao_por_turno)
print("Observações abaixo da meta:", producao_abaixo.size)
print(f"Média abaixo da meta: {media_abaixo:.2f} unidades")
print(f"Produção total no cenário de 3%: {total_cenario:.2f} unidades")
```

``` text
Controle de Produção Boreal
Totais por linha: [1485 1555 1380 1655]
Totais por turno: [2000 2030 2045]
Observações abaixo da meta: 5
Média abaixo da meta: 471.00 unidades
Produção total no cenário de 3%: 6257.25 unidades
```

Um relatório interpretativo pode registrar: as quatro linhas somam 1.485, 1.555, 1.380 e 1.655 unidades, reduzindo os turnos com `axis=1`; os três turnos somam 2.000, 2.030 e 2.045, reduzindo as linhas com `axis=0`. A máscara `producao < meta` seleciona cinco das 12 observações, cuja média é 471 unidades. A Linha 3 tem o menor total, 1.380, e merece acompanhamento. Isso não identifica a causa da diferença. No cenário hipotético, o total passa de 6.075 para 6.257,25 unidades, sem política de arredondamento ou garantia de realização.
