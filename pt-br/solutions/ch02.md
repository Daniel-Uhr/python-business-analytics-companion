# Resoluções — Capítulo 2 — Variáveis, tipos de dados e operações

[Índice do idioma](../README.md) · [Notebook do estudante](../ch02-student.ipynb)

Tente os exercícios antes de consultar as resoluções. Questões abertas admitem outras respostas justificadas.

Este capítulo apresenta as resoluções comentadas dos 17 exercícios do suplemento do Capítulo 2. As respostas seguem a ordem das atividades, inclusive as atualizações de valores. Nos itens abertos, a resposta apresentada é uma possibilidade; o critério é manter o raciocínio, os resultados e seus limites.

<a id="sol-ch02-01"></a>

## Solução do Exercício 01

Precisamos distinguir o que foi planejado do que foi realizado. Cada número recebe um nome, e `print()` mostra os dois valores na ordem em que foram passados como argumentos.

``` python
producao_planejada = 5200
producao_realizada = 4975
print(producao_planejada, producao_realizada)
```

``` text
5200 4975
```

A saída apresenta 5200 unidades planejadas e 4975 realizadas. As atribuições organizam as entradas; ainda não calculam a diferença entre elas.

<a id="sol-ch02-02"></a>

## Solução do Exercício 02

Uma nova atribuição ao mesmo nome substitui sua associação anterior. Não é preciso criar outro nome para representar a versão atual da informação.

``` python
producao_realizada = 5050
producao_realizada
```

``` text
5050
```

`producao_realizada` agora representa 5050. Se uma conta tivesse sido executada antes dessa mudança, seria necessário executá-la novamente para usar a atualização.

<a id="sol-ch02-03"></a>

## Solução do Exercício 03

O custo por unidade inclui uma parte decimal. Após atribuí-lo, consultamos cada variável para verificar sua representação, em vez de deduzir o tipo apenas pelo significado do nome.

``` python
custo_unitario = 18.75
print(type(producao_planejada))
print(type(producao_realizada))
print(type(custo_unitario))
```

``` text
<class 'int'>
<class 'int'>
<class 'float'>
```

As duas produções são `int`; o custo unitário é `float`. Ter unidade monetária não torna um valor automaticamente `float`: o diagnóstico depende da representação efetivamente atribuída.

<a id="sol-ch02-04"></a>

## Solução do Exercício 04

A diferença mantém a ordem planejado menos realizado. O custo total usa a produção realizada como quantidade: multiplicamos unidades produzidas pelo custo de cada unidade.

``` python
print(producao_planejada - producao_realizada)
print(custo_unitario * producao_realizada)
```

``` text
150
94687.5
```

Faltam 150 unidades em relação ao planejamento, e o custo total didático é R\$ 94.687,50. Usar 4975 nesta etapa ignoraria a atualização expressamente solicitada.

<a id="sol-ch02-05"></a>

## Solução do Exercício 05

A diferença entre receita e custos deve ser calculada primeiro. Os parênteses tornam essa ordem explícita; dividimos pela receita da unidade e multiplicamos por 100.

``` python
receita_unidade = 320000
custos_unidade = 236000
margem_unidade = (
    (receita_unidade - custos_unidade) / receita_unidade * 100
)
margem_unidade
```

``` text
26.25
```

A margem simplificada é 26,25%. Ela descreve a parcela da receita que resta após os custos informados; não incorpora outros componentes contábeis que o exercício não forneceu.

<a id="sol-ch02-06"></a>

## Solução do Exercício 06

As aspas delimitam os textos. Para exemplificar uma escolha válida de região, usamos `"  Sul  "`, com espaços antes e depois do nome. Outras escolhas também atendem ao enunciado.

``` python
empresa = "Mercado Central"
regiao = "  Sul  "
print(type(empresa), type(regiao))
```

``` text
<class 'str'> <class 'str'>
```

As duas variáveis contêm strings. Os espaços externos não mudam o tipo: eles fazem parte do conteúdo textual atribuído à região.

<a id="sol-ch02-07"></a>

## Solução do Exercício 07

`upper()` produz a apresentação em maiúsculas, que enviamos diretamente a `print()`. Para a região, guardamos o retorno de `strip()` no mesmo nome, pois o texto limpo será usado depois.

``` python
print(empresa.upper())
regiao = regiao.strip()
print(regiao)
```

``` text
MERCADO CENTRAL
Sul
```

A empresa aparece em maiúsculas, mas sua variável original não foi reatribuída. A região, por sua vez, foi atualizada para o texto sem os espaços externos. Espaços internos não seriam removidos por essa chamada.

<a id="sol-ch02-08"></a>

## Solução do Exercício 08

Usamos o valor booleano `True`, com inicial maiúscula e sem aspas. Depois verificamos o tipo da informação registrada.

``` python
estoque_disponivel = True
type(estoque_disponivel)
```

``` text
bool
```

O resultado é `bool`. A atribuição registra a disponibilidade dada no exercício; ela não consulta um sistema de estoque nem verifica uma quantidade física.

<a id="sol-ch02-09"></a>

## Solução do Exercício 09

Atingir a meta inclui igualá-la ou superá-la. A comparação `>=` expressa esse critério, e a atribuição guarda sua resposta para uso posterior.

``` python
vendas = 86000
meta = 90000
meta_atingida = vendas >= meta
meta_atingida
```

``` text
False
```

`False` indica que R\$ 86.000 não atingem a meta de R\$ 90.000. É a resposta correta à proposição, e não uma mensagem de erro do programa.

<a id="sol-ch02-10"></a>

## Solução do Exercício 10

A primeira pergunta compara texto; a segunda compara valores numéricos. São duas proposições independentes. Nesta resolução, a região escolhida foi Sul e sua caixa foi preservada após a limpeza.

``` python
print(regiao == "Sul")
print(vendas != meta)
```

``` text
True
True
```

As duas respostas são `True` para esta escolha. Se você escolheu outra região ou outra combinação de maiúsculas/minúsculas, a primeira pode ser `False` e estar correta. A segunda permanece `True`, pois 86000 e 90000 são diferentes. Ser diferente da meta não significa necessariamente superá-la.

<a id="sol-ch02-11"></a>

## Solução do Exercício 11

Separamos as entradas dos cálculos. O nome da operação é textual; os cinco valores são atribuídos conforme foram fornecidos, sem inventar informações adicionais.

``` python
operacao = "Centro de Distribuição Orion"
pedidos_programados = 3200
pedidos_entregues = 2985
custo_operacional = 186000
funcionarios = 36
meta_atendimento = 92
print(operacao)
print(
    pedidos_programados,
    pedidos_entregues,
    custo_operacional,
    funcionarios,
    meta_atendimento,
)
```

``` text
Centro de Distribuição Orion
3200 2985 186000 36 92
```

A primeira linha da saída identifica a operação. A segunda apresenta, na ordem, pedidos programados, pedidos entregues, custo operacional, funcionários e meta percentual. Registrar a meta como 92 significa usar a escala percentual, não a proporção 0,92.

<a id="sol-ch02-12"></a>

## Solução do Exercício 12

O objetivo é diagnosticar as entradas existentes. Escolhemos o nome, a quantidade entregue e a meta; não precisamos criar um tipo novo para completar a verificação.

``` python
print(type(operacao))
print(type(pedidos_entregues))
print(type(meta_atendimento))
```

``` text
<class 'str'>
<class 'int'>
<class 'int'>
```

`operacao` é `str`; `pedidos_entregues` e `meta_atendimento` são `int`. Três variáveis não precisam ter três tipos diferentes. A taxa calculada adiante será `float`. Para criar o nome completo da operação como texto, mantenha as aspas: várias palavras sem aspas podem formar uma expressão inválida, não apenas um nome inexistente.

<a id="sol-ch02-13"></a>

## Solução do Exercício 13

A diferença responde quantos pedidos programados não foram entregues. A taxa usa o total programado como denominador, pois queremos a parcela desse total que foi atendida.

``` python
pedidos_nao_entregues = pedidos_programados - pedidos_entregues
taxa_atendimento = pedidos_entregues / pedidos_programados * 100
print(pedidos_nao_entregues)
print(taxa_atendimento)
```

``` text
215
93.28125
```

São 215 pedidos não entregues e taxa de 93,28125%, aproximadamente 93,28%. Inverter numerador e denominador deixaria de medir a participação das entregas no total programado. A multiplicação por 100 coloca a taxa na mesma escala da meta.

<a id="sol-ch02-14"></a>

## Solução do Exercício 14

Cada denominador define um indicador. Dividir custo por entregas produz reais por entrega; dividir entregas pela equipe produz entregas por funcionário. As duas contas usam o volume efetivamente entregue.

``` python
custo_por_entrega = custo_operacional / pedidos_entregues
entregas_por_funcionario = pedidos_entregues / funcionarios
print(custo_por_entrega)
print(entregas_por_funcionario)
```

``` text
62.311557788944725
82.91666666666667
```

O custo operacional médio é aproximadamente R\$ 62,31 por entrega, e a relação entre entregas e equipe é de aproximadamente 82,92 por funcionário. São médias descritivas: não informam que cada entrega custou o mesmo, nem que cada pessoa realizou exatamente esse volume. Isoladamente, também não demonstram eficiência ou suas causas.

<a id="sol-ch02-15"></a>

## Solução do Exercício 15

O critério é taxa maior ou igual à meta. A comparação produz um booleano que podemos guardar e diagnosticar com `type()`; não é necessário usar uma condicional.

``` python
meta_atingida = taxa_atendimento >= meta_atendimento
print(meta_atingida)
print(type(meta_atingida))
```

``` text
True
<class 'bool'>
```

`True` confirma que a taxa calculada supera ou iguala 92%. Neste caso, ela é superior. O diagnóstico é `bool`. Usar `=` no lugar de `>=` faria uma atribuição em vez de avaliar o critério; a resposta tampouco explica por que a meta foi alcançada.

<a id="sol-ch02-16"></a>

## Solução do Exercício 16

O relatório conecta cada rótulo à variável correspondente. As especificações `.2f` controlam somente a apresentação das três medidas; as quantidades inteiras e o booleano mantêm sua forma própria.

``` python
print(f"Operação: {operacao}")
print(f"Pedidos não entregues: {pedidos_nao_entregues}")
print(f"Taxa de atendimento: {taxa_atendimento:.2f}%")
print(f"Custo por entrega: R$ {custo_por_entrega:.2f}")
print(f"Entregas por funcionário: {entregas_por_funcionario:.2f}")
print(f"Meta atingida: {meta_atingida}")
```

``` text
Operação: Centro de Distribuição Orion
Pedidos não entregues: 215
Taxa de atendimento: 93.28%
Custo por entrega: R$ 62.31
Entregas por funcionário: 82.92
Meta atingida: True
```

Os seis campos aparecem com seus significados explícitos. O símbolo percentual é texto acrescentado à taxa já multiplicada por 100. A formatação não altera os valores usados nas contas e na comparação. Se as entradas mudarem, reexecute os cálculos antes do relatório.

<a id="sol-ch02-17"></a>

## Solução do Exercício 17

Uma conclusão reúne os números relevantes e responde à pergunta do caso. O texto abaixo é uma possibilidade; outras redações que preservem os resultados e seus limites também são válidas.

A taxa de atendimento foi de aproximadamente 93,28%, portanto a meta de 92% foi atingida. Dos 3.200 pedidos programados, 215 não foram entregues. O custo de R\$ 62,31 por entrega descreve a relação média entre custo operacional e entregas, enquanto as 82,92 entregas por funcionário relacionam o volume entregue ao tamanho da equipe. Sem referência de comparação ou informações adicionais, esses indicadores não permitem classificar o desempenho como bom ou ruim nem explicar suas causas.
