## Solution to Exercise 01

We need to distinguish planned output from actual output. Each number receives a name, and `print()` displays the values in the order supplied as arguments.

``` python
planned_production = 5200
actual_production = 4975
print(planned_production, actual_production)
```

``` text
5200 4975
```

The output shows 5200 planned units and 4975 actual units. The assignments organize the inputs; they do not yet calculate the difference.

<a id="sol-ch02-02"></a>

## Solution to Exercise 02

A new assignment to the same name replaces its previous association. We do not need a different name to represent the current version of the information.

``` python
actual_production = 5050
actual_production
```

``` text
5050
```

`actual_production` now represents 5050. A calculation run before this change would need to be rerun to use the update.

<a id="sol-ch02-03"></a>

## Solution to Exercise 03

Unit cost includes a decimal part. After assigning it, we inspect each variable rather than inferring its type solely from the meaning of its name.

``` python
unit_cost = 18.75
print(type(planned_production))
print(type(actual_production))
print(type(unit_cost))
```

``` text
<class 'int'>
<class 'int'>
<class 'float'>
```

Both production counts are `int`; unit cost is `float`. A monetary unit does not automatically make a value a `float`: the diagnostic reflects its actual representation.

<a id="sol-ch02-04"></a>

## Solution to Exercise 04

The gap is planned minus actual production. Total cost uses actual production as the quantity: multiply the units produced by the cost of each unit.

``` python
print(planned_production - actual_production)
print(unit_cost * actual_production)
```

``` text
150
94687.5
```

Actual production is 150 units below plan, and the teaching total cost is USD 94,687.50. Using 4975 here would ignore the requested update.

## Solution to Exercise 05

Calculate the difference between revenue and costs first. Parentheses make that order explicit; then divide by the unit revenue and multiply by 100.

``` python
unit_revenue = 320000
unit_costs = 236000
unit_margin = (unit_revenue - unit_costs) / unit_revenue * 100
unit_margin
```

``` text
26.25
```

The simplified margin is 26.25%. It describes the share of revenue remaining after the specified costs; it does not incorporate accounting items the exercise did not supply.

<a id="sol-ch02-06"></a>

## Solution to Exercise 06

Quotation marks delimit the text. We use `"  South  "`, with spaces before and after the name, as one valid choice of region. Other choices also meet the prompt.

``` python
company = "Central Market"
region = "  South  "
print(type(company), type(region))
```

``` text
<class 'str'> <class 'str'>
```

Both variables contain strings. Outer spaces do not change the type: they are part of the text assigned to the region.

<a id="sol-ch02-07"></a>

## Solution to Exercise 07

`upper()` produces the uppercase presentation, which we send directly to `print()`. For the region, we assign the result of `strip()` to the same name because the cleaned text will be used later.

``` python
print(company.upper())
region = region.strip()
print(region)
```

``` text
CENTRAL MARKET
South
```

The company is displayed in uppercase, but its original variable was not reassigned. The region was updated to the text without outer spaces. This call would not remove internal spaces.

## Solution to Exercise 08

Use the Boolean value `True`, capitalized and without quotation marks. Then check the type of the recorded information.

``` python
stock_available = True
type(stock_available)
```

``` text
bool
```

The result is `bool`. The assignment records the availability supplied in the exercise; it does not query an inventory system or check a physical quantity.

## Solution to Exercise 09

Meeting the target includes reaching it exactly or exceeding it. The `>=` comparison expresses that criterion, and the assignment stores its answer for later use.

``` python
sales = 86000
target = 90000
target_met = sales >= target
target_met
```

``` text
False
```

`False` means that USD 86,000 does not meet the USD 90,000 target. It is the correct answer to the proposition, not a program error.

## Solution to Exercise 10

The first question compares text; the second compares numbers. They are separate propositions. This solution chose South and preserved its capitalization during cleaning.

``` python
print(region == "South")
print(sales != target)
```

``` text
True
True
```

Both answers are `True` for this choice. If you chose another region or capitalization, the first answer may correctly be `False`. The second remains `True` because 86000 differs from 90000. Being different from a target does not necessarily mean exceeding it.

## Solution to Exercise 11

Separate inputs from calculations. The operation name is text, and the five values are assigned as supplied, without inventing additional information.

``` python
operation = "Orion Distribution Center"
scheduled_orders = 3200
delivered_orders = 2985
operating_cost = 186000
employees = 36
target_fulfillment = 92
print(operation)
print(
    scheduled_orders,
    delivered_orders,
    operating_cost,
    employees,
    target_fulfillment,
)
```

``` text
Orion Distribution Center
3200 2985 186000 36 92
```

The first output line identifies the operation. The second shows scheduled orders, delivered orders, operating cost, employees, and the percentage target, in that order. Storing the target as 92 uses the percentage scale, rather than the proportion 0.92.

<a id="sol-ch02-12"></a>

## Solution to Exercise 12

The goal is to inspect the existing inputs. We choose the name, delivered quantity, and target; no new type needs to be created to complete the check.

``` python
print(type(operation))
print(type(delivered_orders))
print(type(target_fulfillment))
```

``` text
<class 'str'>
<class 'int'>
<class 'int'>
```

`operation` is `str`; `delivered_orders` and `target_fulfillment` are `int`. Three variables need not have three different types. The rate calculated later will be a `float`. Keep the quotation marks around the full operation name: several words without quotes can form an invalid expression, rather than merely an undefined name.

<a id="sol-ch02-13"></a>

## Solution to Exercise 13

The difference tells us how many scheduled orders were not delivered. The rate uses scheduled orders as the denominator because we want the share of that total that was fulfilled.

``` python
undelivered_orders = scheduled_orders - delivered_orders
fulfillment_rate = delivered_orders / scheduled_orders * 100
print(undelivered_orders)
print(fulfillment_rate)
```

``` text
215
93.28125
```

There are 215 undelivered orders, and fulfillment is 93.28125%, or approximately 93.28%. Reversing numerator and denominator would no longer measure deliveries as a share of scheduled orders. Multiplying by 100 puts the rate on the same scale as the target.

<a id="sol-ch02-14"></a>

## Solution to Exercise 14

Each denominator defines a metric. Cost divided by deliveries produces USD per delivery; deliveries divided by team size produces deliveries per employee. Both use the volume actually delivered.

``` python
cost_per_delivery = operating_cost / delivered_orders
deliveries_per_employee = delivered_orders / employees
print(cost_per_delivery)
print(deliveries_per_employee)
```

``` text
62.311557788944725
82.91666666666667
```

Average operating cost is approximately USD 62.31 per delivery, and the ratio of deliveries to staff is approximately 82.92 per employee. These descriptive averages do not imply that every delivery cost the same or that every person handled exactly that volume. Alone, they do not establish efficiency or its causes.

<a id="sol-ch02-15"></a>

## Solution to Exercise 15

The criterion is a rate greater than or equal to the target. The comparison produces a Boolean that we can store and inspect with `type()`; no conditional statement is needed.

``` python
target_met = fulfillment_rate >= target_fulfillment
print(target_met)
print(type(target_met))
```

``` text
True
<class 'bool'>
```

`True` confirms that the calculated rate is at least 92%. Here it is higher. The type is `bool`. Using `=` instead of `>=` would assign a value rather than evaluate the criterion; the answer also does not explain why the target was met.

<a id="sol-ch02-16"></a>

## Solution to Exercise 16

The report connects each label to its corresponding variable. The `.2f` specifications control only the presentation of the three metrics; integer quantities and the Boolean retain their own forms.

``` python
print(f"Operation: {operation}")
print(f"Undelivered orders: {undelivered_orders}")
print(f"Fulfillment rate: {fulfillment_rate:.2f}%")
print(f"Cost per delivery: USD {cost_per_delivery:.2f}")
print(f"Deliveries per employee: {deliveries_per_employee:.2f}")
print(f"Target met: {target_met}")
```

``` text
Operation: Orion Distribution Center
Undelivered orders: 215
Fulfillment rate: 93.28%
Cost per delivery: USD 62.31
Deliveries per employee: 82.92
Target met: True
```

All six fields have explicit meanings. The percent sign is text added to a rate already multiplied by 100. Formatting does not change the values used in calculations or the comparison. If inputs change, rerun the calculations before the report.

<a id="sol-ch02-17"></a>

## Solution to Exercise 17

A conclusion brings together the relevant numbers and answers the case question. The text below is one possible answer; other wording that preserves the results and their limits is also valid.

The fulfillment rate was approximately 93.28%, so the 92% target was met. Of the 3,200 scheduled orders, 215 were not delivered. Cost of USD 62.31 per delivery describes the average relationship between operating cost and deliveries, while 82.92 deliveries per employee relates delivered volume to team size. Without a comparison benchmark or additional information, these metrics cannot establish whether performance was good or bad or explain its causes.
