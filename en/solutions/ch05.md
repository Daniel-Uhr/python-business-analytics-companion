## Solution to Exercise 01

The operation needs no input: it always displays the same message. Its definition therefore has empty parentheses. The print statement belongs to the indented body; the call sits outside it and requests execution after the function has been defined.

``` python
def start_report():
    print('Report started.')
start_report()
```

``` text
Report started.
```

The call produces the output; defining the function alone does not. This function communicates a message and ends without an explicit `return`, so its return value is `None`. The exercise does not require a numeric result.

<a id="sol-ch05-02"></a>

## Solution to Exercise 02

The quantity can change between calls. We use `production` as a parameter and insert its value into the message with an f-string. The word “units” communicates what the number represents without becoming part of the numeric input.

``` python
def show_production(production):
    print(f'Production: {production} units')
show_production(850)
```

``` text
Production: 850 units
```

`production` is the parameter in the definition; 850 is the argument in this call. The function displays 850 units but does not return that number. A different quantity could use the same definition.

## Solution to Exercise 03

The prompt specifies the subtraction order. The first parameter represents actual production and the second represents planned production. The local variable `difference` makes the calculation easy to read before its result is displayed.

``` python
def show_difference(production, planned):
    difference = production - planned
    print(f'Difference: {difference} units')
show_difference(850, 800)
```

``` text
Difference: 50 units
```

The difference is positive: actual production exceeds the plan by 50 units. This is an absolute difference, not a percentage rate. Reversing the arguments would change its meaning and would not answer the stated question.

## Solution to Exercise 04

Multiplying cost per unit by quantity produces total cost in the same currency. The function should return a number, leaving monetary formatting outside it. The result stored in `cost` can then participate in another calculation.

``` python
def calculate_total_cost(unit_cost, quantity):
    total_cost = unit_cost * quantity
    return total_cost
cost = calculate_total_cost(18.5, 240)
print(f'USD {cost:.2f}')
```

``` text
USD 4440.00
```

The return value is 4440, corresponding to USD 4,440.00. The currency label is added only for display; `cost` remains numeric. This keeps presentation separate from the calculation.

## Solution to Exercise 05

This exercise depends on the previous result. We divide the part, `cost`, by the reference whole, `budget`, and multiply by 100. Both quantities share the same currency, and the supplied budget is positive.

``` python
budget = 5000
budget_percentage = cost / budget * 100
print(f'{budget_percentage:.2f}%')
```

``` text
88.80%
```

Cost represents 88.80% of the budget. This describes the relationship between the supplied values; it does not establish that spending was efficient. Reusing the return value avoids repeating the unit-cost multiplication.

## Solution to Exercise 06

Price and discount are inputs, while the rule stays the same across all three calls. Dividing the discount by 100 expresses it as a proportion. Subtracting that proportion from 1 gives the share of the price remaining after the discount, and multiplication gives the final price.

``` python
def calculate_discounted_price(price, discount):
    final_price = price * (1 - discount / 100)
    return final_price
print(calculate_discounted_price(200, 10))
print(calculate_discounted_price(350, 8))
print(calculate_discounted_price(120, 5))
```

``` text
180.0
322.0
114.0
```

The final prices are 180, 322, and 114. Outputs ending in `.0` still represent numeric values. The function keeps the formula in one definition, accepts different inputs, and makes the rule easier to review without searching for three copies.

## Solution to Exercise 07

The list is an input, and the loop handles each element. `lead_times` represents the collection; `lead_time` represents one value per iteration. Since the task is presentation, we print inside the loop without constructing a total.

``` python
def show_lead_times(lead_times):
    for lead_time in lead_times:
        print(f'{lead_time} days')
show_lead_times([3, 5, 2, 7])
```

``` text
3 days
5 days
2 days
7 days
```

The four lead times appear in their original order with their unit. The function finishes and returns `None`, which is appropriate for this display task. No mean, sum, or modification of the list is required.

## Solution to Exercise 08

The counter starts at zero inside the function. The comparison uses `<` because the question asks for levels below the minimum. When the condition holds, we add one occurrence, not the inventory level itself. The return follows traversal.

``` python
def count_low_inventory(inventory_levels, minimum_inventory):
    counter = 0
    for inventory in inventory_levels:
        if inventory < minimum_inventory:
            counter = counter + 1
    return counter
low_count = count_low_inventory([18, 7, 12, 5, 20], 10)
print(low_count)
```

``` text
2
```

Inventory levels 7 and 5 satisfy the condition, so the return value is 2. A level exactly equal to the minimum would not enter this count. The result counts entries below the threshold, not the units needed to replenish inventory.

## Solution to Exercise 09

The accumulator starts at zero and incorporates each value. `return total` is aligned with `for`, outside the loop body, so that it returns the complete sum. The built-in comparison uses the same list without modifying its elements.

``` python
def calculate_manual_total(values):
    total = 0
    for value in values:
        total = total + value
    return total
values = [45, 60, 55, 40]
print(calculate_manual_total(values))
print(sum(values))
```

``` text
200
200
```

Both forms produce 200, confirming agreement for the supplied list. The manual function exposes the accumulation process; `sum()` is a more direct way to perform this simple summation.

## Solution to Exercise 10

Each call receives one inventory level and returns a text classification. The comparison selects one of two return paths. Equality belongs to the second path because the first condition is strictly less than the minimum.

``` python
def classify_inventory(inventory, minimum_inventory):
    if inventory < minimum_inventory:
        return 'Restocking needed'
    else:
        return 'Sufficient inventory'
print(classify_inventory(7, 10))
```

``` text
Restocking needed
```

Because 7 is less than 10, the result is “Restocking needed.” This classifies the situation under the illustrative criterion; it does not calculate an order quantity or account for future demand.

## Solution to Exercise 11

The chosen name communicates the operation, and the first statement in the body is a documenting string. We use `max` to obtain the largest element and return it directly. A separate manual traversal is unnecessary when a built-in function meets the need.

``` python
def find_longest_time(times):
    """Returns the longest time observed in a list."""
    return max(times)
print(find_longest_time([12, 9, 15, 11]))
```

``` text
15
```

The return value is 15. We do not add “minutes” or “hours” because that information was not supplied. The form of `max` used here requires a nonempty list. Other clear names and correct solutions also satisfy the prompt.

## Solution to Exercise 12

We need to track two quantities for the same selection. Inside the `if`, the counter gains one occurrence and the accumulator gains the selected value. At the end, a dictionary associates each result with a name, combining them into a single returned object.

``` python
def summarize_selected_values(values, threshold):
    quantity = 0
    total = 0
    for value in values:
        if value >= threshold:
            quantity = quantity + 1
            total = total + value
    return {'count': quantity, 'total': total}
summary = summarize_selected_values([72, 88, 91, 65, 84], 80)
print(summary)
```

``` text
{'count': 3, 'total': 263}
```

Values 88, 91, and 84 meet the threshold: three elements with a sum of 263. The sum includes their full values, not just their differences from 80. Keys distinguish count from total without relying on the position of each result.

## Solution to Exercise 13

One option separates individual classification, counting days below target, cumulative production, and surplus production above target. These operations answer different questions and can supply values to a shared report. The report can then reuse the results without rebuilding their rules.

| Operation | Inputs | Result |
|----|----|----|
| Classify production | One production value and target | Below, exact, or above |
| Count days below | Production list and target | Number of days |
| Accumulate production | Production list | Total units |
| Accumulate surplus | Production list and target | Sum of positive excess amounts |

The following solutions use `classify_production`, `count_days_below_target`, `calculate_cumulative_production`, and `calculate_surplus_production`. These names and this division are one valid choice, not the only one. An alternative should make inputs and outputs explicit and avoid unnecessary duplication of rules.

## Solution to Exercise 14

First we check whether production is below the target. If not, we check equality; the remaining case is above target. Each branch returns a classification. The external loop supplies one observation at a time to the same function.

``` python
daily_production = [480, 520, 505, 450, 540, 510]
daily_target = 500

def classify_production(production, target):
    if production < target:
        return 'Below target'
    elif production == target:
        return 'Exact target'
    else:
        return 'Above target'
for production in daily_production:
    print(f'{production}: {classify_production(production, daily_target)}')
```

``` text
480: Below target
520: Above target
505: Above target
450: Below target
540: Above target
510: Above target
```

Production values 480 and 450 are below target; 520, 505, 540, and 510 are above it. No observation equals 500, but the rule retains the “Exact target” category. Its absence from the output reflects the data, not a missing branch.

## Solution to Exercise 15

The local counter starts at zero on each call. The test `production < target` selects the relevant days. We add one occurrence per selected day and return the count after examining the entire list.

``` python
def count_days_below_target(production_values, target):
    counter = 0
    for production in production_values:
        if production < target:
            counter = counter + 1
    return counter
days_below = count_days_below_target(daily_production, daily_target)
print(days_below)
```

``` text
2
```

The return value is 2: two of the six days fell below 500 units. This metric does not measure total production shortfall. Storing it in `days_below` lets the report reuse it without calling the counting function inside the print statement.

<a id="sol-ch05-16"></a>

## Solution to Exercise 16

This operation includes every day, not only those meeting the target. The accumulator starts at zero, receives each production value, and is returned after the loop. The comparison with `sum` uses exactly the same list.

``` python
def calculate_cumulative_production(production_values):
    total = 0
    for production in production_values:
        total = total + production
    return total
cumulative_production = calculate_cumulative_production(daily_production)
print(cumulative_production)
print(sum(daily_production))
```

``` text
3005
3005
```

Both methods produce 3005 units. This is the total over the observed period, not mean daily production. Agreement confirms the sum for these data, while the manual version exposes the accumulation process.

<a id="sol-ch05-17"></a>

## Solution to Exercise 17

The signature receives the list and target, so the body does not depend on a hard-coded 500. The test selects production values above the target. For each, we calculate `production - target` and add only that difference to the accumulator.

``` python
def calculate_surplus_production(production_values, target):
    total_surplus = 0
    for production in production_values:
        if production > target:
            surplus = production - target
            total_surplus = total_surplus + surplus
    return total_surplus
surplus_production = (
    calculate_surplus_production(daily_production, daily_target)
)
print(surplus_production)
```

``` text
75
```

The excess amounts are 20, 5, 40, and 10, totaling 75 units. Below-target days do not reduce this metric. Net production relative to the cumulative target would be a different measure: 3005 − 6 × 500 = 5. We also do not add the full production values of above-target days, as in the selection in Exercise 12. The verbal rule determines which amount enters the sum.

## Solution to Exercise 18

The report depends on the definitions and return values from earlier exercises. We apply the classification function again to the six values and use the stored metrics. `len` supplies the number of days, while `\n` in messages visually separates the report sections.

``` python
print('Orion Manufacturing')
print('\nClassifications:')
for production in daily_production:
    classification = classify_production(production, daily_target)
    print(f'{production}: {classification}')
print(f'\nDays observed: {len(daily_production)}')
print(f'Days below target: {days_below}')
print(f'Cumulative production: {cumulative_production} units')
print(f'Surplus production: {surplus_production} units')
```

``` text
Orion Manufacturing

Classifications:
480: Below target
520: Above target
505: Above target
450: Below target
540: Above target
510: Above target

Days observed: 6
Days below target: 2
Cumulative production: 3005 units
Surplus production: 75 units
```

One possible four-sentence conclusion is: “Among the six observed days, two production values fell below target and four exceeded it, with none exactly on target. Cumulative production was 3,005 units. Surplus amounts on above-target days totaled 75 units, without subtracting below-target shortfalls. These results describe the illustrative data and do not explain the causes of differences across days.”

The interpretation follows the programmed rules. Day count, total production, and surplus are distinct metrics; reporting one does not replace the others.
