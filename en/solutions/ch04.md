## Solution to Exercise 01

First compare each metric with its own target. The margin does not reach 30%, whereas revenue exceeds USD 200,000. In this answer, we apply `not` to the revenue comparison.

``` python
margin = 28
margin_target = 30
revenue = 210000
revenue_target = 200000
print(margin >= margin_target and revenue >= revenue_target)
print(margin >= margin_target or revenue >= revenue_target)
print(not revenue >= revenue_target)
```

``` text
False
True
False
```

`and` returns `False` because one criterion fails. `or` returns `True` because revenue meets its criterion. The revenue comparison is true, so its negation is false. If you chose to negate the margin comparison, obtaining `True` is also correct, provided you explain that choice.

## Solution to Exercise 02

The action depends on a strict comparison: inventory must be below 40. The header ends with a colon, and the print statement belongs to its indented block.

``` python
inventory = 35
minimum_inventory = 40
if inventory < minimum_inventory:
    print('Restock inventory.')
```

``` text
Restock inventory.
```

Since 35 is below 40, the message appears. The code only signals a need to restock; it does not increase inventory. If inventory were exactly at the minimum, this `if` would not produce the message.

## Solution to Exercise 04

The test of 100 comes first because every value satisfying it also satisfies the test of 80. The chain must select the highest applicable category under this rule.

``` python
productivity = 92
if productivity >= 100:
    print('High')
elif productivity >= 80:
    print('Adequate')
else:
    print('Needs attention')
```

``` text
Adequate
```

At 92 units, the first test fails and the second passes. Starting with `>= 80` would prematurely classify values of 100 or more as adequate. A correct result for 92 alone would not validate the rule ordering.

## Solution to Exercise 07

The name `value` receives one element per pass. The f-string inserts that element into the message. Because `print` is inside the loop, each observation gets its own line.

``` python
values = [12, 15, 11, 18]
for value in values:
    print(f'Value: {value}')
```

``` text
Value: 12
Value: 15
Value: 11
Value: 18
```

The order remains 12, 15, 11, and 18. The loop neither sorts the list nor changes its elements. The loop variable contains a value, not a position.

## Solution to Exercise 08

Initialize both variables before traversal. On each pass, add the observed value to the total but only one unit to the counter. The `values` list must already be defined by Exercise 07.

``` python
total = 0
counter = 0
for value in values:
    total = total + value
    counter = counter + 1
print(total, counter)
print(sum(values), len(values))
```

``` text
56 4
56 4
```

Both lines show 56 and 4. The first comes from the explicit procedure, the second from built-in functions. Their agreement checks the calculation for this list. Reinitializing the variables to zero prevents an earlier execution’s results from being accumulated again.

## Solution to Exercise 09

## Solution to Exercise 10

The test occurs before each pass. Printing precedes subtraction, so we see the positive state that allowed entry into the block.

``` python
pending_items = 4
while pending_items > 0:
    print(pending_items)
    pending_items = pending_items - 1
```

``` text
4
3
2
1
```

After printing 1, assignment reduces pending items to zero. The next test fails and ends repetition. Without `pending_items = pending_items - 1`, the state would remain at four and the loop would not terminate through this condition.

## Solution to Exercise 11

In the first fragment, a negative ends traversal. In the second, it ends only the current pass. Placing `print` after the test keeps negatives out of the output in both cases.

``` python
values = [8, 12, -1, 15]
for value in values:
    if value < 0:
        break
    print(value)
```

``` text
8
12
```

``` python
values = [8, -1, 12, -2, 15]
for value in values:
    if value < 0:
        continue
    print(value)
```

``` text
8
12
15
```

The first fragment shows 8 and 12 and never reaches 15. The second shows 8, 12, and 15 because it proceeds after each negative. Both lists remain intact; the execution path changes.

## Solution to Exercise 12

The condition must control both updates. The counter and accumulator updates belong inside the `if`; initialization comes before the `for`, and printing follows it.

``` python
scores = [72, 88, 91, 65, 84]
count = 0
selected_total = 0
for score in scores:
    if score >= 80:
        count = count + 1
        selected_total = selected_total + score
print(count)
print(selected_total)
```

``` text
3
263
```

The contributing values are 88, 91, and 84: three values summing to 263. The loop visits 72 and 65 but they do not update the results. The counter measures how many were selected; the accumulator measures the subset’s sum.

## Solution to Exercise 13

Start with the five-minute boundary. The `elif` is reached only when waiting time exceeds five; testing `<= target` there identifies the intermediate band. The `else` covers times above seven minutes.

``` python
wait_times = [4, 12, 7, 3, 15, 8, 5, 11, 6, 2]
target = 7
for time in wait_times:
    if time <= 5:
        print(f'{time}: fast service')
    elif time <= target:
        print(f'{time}: within target, over 5 minutes')
    else:
        print(f'{time}: above target')
```

``` text
4: fast service
12: above target
7: within target, over 5 minutes
3: fast service
15: above target
8: above target
5: fast service
11: above target
6: within target, over 5 minutes
2: fast service
```

The bands are mutually exclusive. Fast interactions also meet the overall seven-minute target but receive their own category. Testing `<= 7` first would absorb fast interactions and prevent this separation. Output preserves the order of all ten records.

## Solution to Exercise 14

The time sum must include every record, so its update belongs inside the `for` and before classification. Each branch increments only its band’s counter. Reinitialize everything so this new traversal does not duplicate earlier results.

``` python
wait_times = [4, 12, 7, 3, 15, 8, 5, 11, 6, 2]
target = 7
fast_count = 0
within_target_band_count = 0
above_target_count = 0
total = 0
for time in wait_times:
    total = total + time
    if time <= 5:
        fast_count = fast_count + 1
        print(f'{time}: fast service')
    elif time <= target:
        within_target_band_count = within_target_band_count + 1
        print(f'{time}: within target, over 5 minutes')
    else:
        above_target_count = above_target_count + 1
        print(f'{time}: above target')
```

``` text
4: fast service
12: above target
7: within target, over 5 minutes
3: fast service
15: above target
8: above target
5: fast service
11: above target
6: within target, over 5 minutes
2: fast service
```

The final variables hold 4 fast interactions, 2 in the intermediate band, 4 above target, and a sum of 73 minutes. Individual messages repeat the previous classification; totals remain stored for the next calculation. The 73 minutes add different people’s waiting times and do not necessarily measure the center’s operating duration.

## Solution to Exercise 15

Adding the three counters provides a common denominator. Divide the time sum by that count to obtain the mean, and divide the above-target count by the same total, multiplying by 100 for the percentage.

``` python
count = fast_count + within_target_band_count + above_target_count
mean = total / count
above_target_percentage = above_target_count / count * 100
print(count)
print(f'{mean:.2f}')
print(f'{above_target_percentage:.2f}%')
```

``` text
10
7.30
40.00%
```

There are 10 interactions, a mean of 7.30 minutes, and 40% above target. The `:.2f` format controls the two-decimal display. Division is valid because the total is positive. The mean alone does not reveal the distribution across bands; we also need the counts.

## Solution to Exercise 16

The counter starts at zero. The condition explicitly states both failure to meet the target and the additional inclusive ten-minute threshold. Use the same list and target defined in the case.

``` python
long_waits = 0
for time in wait_times:
    if time > target and time >= 10:
        long_waits = long_waits + 1
print(long_waits)
```

``` text
3
```

Waits of 12, 15, and 11 minutes satisfy the rule, producing three occurrences. The eight-minute wait exceeds target but does not reach ten. With the target fixed at seven, every value of at least ten already exceeds it: the first test is numerically redundant, although it states both criteria in the prompt. Ten would be included by the rule even though it does not occur in the list.

## Solution to Exercise 17

The report brings together previously calculated values. Each f-string places a variable in the appropriate message; mean and percentage use two decimal places. The unit “minutes” distinguishes the mean from a count.

``` python

print(f'Fast interactions: {fast_count}')

print(f'Percentage above target: {above_target_percentage:.2f}%')

```

``` text
Prism Customer Support Center
Total: 10
Fast interactions: 4
Within target, over 5 minutes: 2
Above target: 4
Mean: 7.30 minutes
Percentage above target: 40.00%
Particularly long waits: 3
```

The intermediate row shows two interactions, but six meet the overall target: four fast plus two intermediate. These six are not a fourth band to add to the others. The three exclusive bands sum to ten, and the three particularly long waits form a subset of the four above-target interactions.
