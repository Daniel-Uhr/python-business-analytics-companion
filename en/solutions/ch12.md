## Solution to Exercise 01

Each row represents a record. Lists in the same order associate R1–R4 with the four dates. `dtype` inspects the text column before conversion. The block below combines construction and conversion for Exercises 01–03, following the received solution. The `value` column, containing 500, 700, 600, and 800, is additional illustrative information: it was not required, is not used in the calculations, and has no specified currency.

``` python
records = pd.DataFrame(
    {
        'record_id': ['R1', 'R2', 'R3', 'R4'],
        'raw_date': ['01/05/2026', '02/18/2026', '02/31/2026', '03/10/2026'],
        'value': [500, 700, 600, 800]
    }
)
print('Initial type:', records['raw_date'].dtype)
records['date'] = pd.to_datetime(
    records['raw_date'],
    format='%m/%d/%Y',
    errors='coerce'
)
print(records)
print('Invalid dates:', records['date'].isna().sum())
```

``` text
3        R4  03/10/2026    800 2026-03-10

```

The first print identifies text, without temporal operations yet. `raw_date` is retained while `date` holds the converted result. A student who built only the IDs and dates also met Exercise 01. The following items interpret the conversion and unresolved value in this output.

## Solution to Exercise 02

The `pd.to_datetime` call shown in Solution 01 reads `raw_date`, applies `%m/%d/%Y`, and uses `errors="coerce"`. Saving the result in another column separates the received input from its temporal interpretation. The `isna()` mask and its sum count converted values that are missing.

R1 is January 5, R2 is February 18, and R4 is March 10, 2026. R3 becomes `NaT`; the invalid-date count is 1. Rebuilding the dataset is unnecessary for this item.

## Solution to Exercise 03

R3 contains `02/31/2026`. The characters follow the declared format, but the calendar does not permit that day. This distinction between format and validity explains the `NaT` in Solution 01.

Document the unresolved entry and consult the source. Nothing supports choosing February 28, March 3, or any other replacement. Keeping the raw text preserves traceability; no replacement is made.

## Solution to Exercise 05

## Solution to Exercise 06

In Solution 05, the ISO boundaries `2026-01-01` and `2026-02-28` are converted to dates. `between` includes both endpoints, and the outer brackets select rows of `sorted_records` whose condition is true.

R1 and R2 belong to the interval. R4 is in March; R3 has no valid date and does not pass the mask. Selection preserves the unresolved entry in the original dataset and does not establish which month R3 belongs to.

## Solution to Exercise 07

Count missing dates and build a valid-date view to inspect its endpoints. `dropna(subset=["date"])` affects that view; it does not overwrite `records`. After sorting, `iloc[0]` and `iloc[-1]` access the first and last positions. `tolist()` turns selections into readable lists. The mask in `.loc` retrieves the raw unresolved text.

``` python
invalid_dates = records['date'].isna().sum()
sorted_valid_dates = records.dropna(subset=['date']).sort_values('date')
interval_ids = selected_records['record_id'].tolist()
unresolved_text = records.loc[records['date'].isna(), 'raw_date'].tolist()
print('One invalid date:', invalid_dates == 1)
print('First valid date:', sorted_valid_dates.iloc[0]['date'])
print('Last valid date:', sorted_valid_dates.iloc[-1]['date'])
print('Records in the interval:', interval_ids)
print('Unresolved original text:', unresolved_text)
```

``` text
One invalid date: True
First valid date: 2026-01-05 00:00:00
Last valid date: 2026-03-10 00:00:00
Records in the interval: ['R1', 'R2']
Unresolved original text: ['02/31/2026']
```

The checks show one invalid date, endpoints on January 5 and March 10, IDs R1/R2 in the interval, and unresolved text `02/31/2026`. These case-specific checks confirm the diagnosis and preserve evidence without correcting unknown information.

## Solution to Exercise 13

Sort `monthly` by period, add absolute change with `diff()`, and multiply fractional change from `pct_change()` by 100. Each comparison uses the previous row of the sorted series.

``` python
monthly = monthly.sort_values('month_ref')
monthly['absolute_change'] = monthly['total_revenue'].diff()
monthly['percent_change'] = monthly['total_revenue'].pct_change() * 100

```

``` text
1   2026-02           2600      2            100.0        4.000000
2   2026-03           3300      2            700.0       26.923077
```

February increases by \$100, or 4% of \$2,500. March increases by \$700, or about 26.92% of \$2,600. January has no earlier observation and remains missing in both change columns. Do not fill it with zero or assign a cause to the increases.

## Solution to Exercise 14

Use calendar quarters as the frequency and summed observed revenue as the indicator. Extract `year` and `quarter`, then group by both columns. Including the year prevents combining first quarters from different years. Selecting revenue before `sum()` defines what is aggregated.

``` python
sales['year'] = sales['date'].dt.year
sales['quarter'] = sales['date'].dt.quarter
quarterly_revenue = sales.groupby(['year', 'quarter'])['revenue'].sum()
quarterly_reconciliation = quarterly_revenue.sum() == sales['revenue'].sum()
print(quarterly_revenue)
print('Quarterly reconciliation:', quarterly_reconciliation)
```

``` text
year  quarter
2026  1          8400
Name: revenue, dtype: int64
Quarterly reconciliation: True
```

All six sales belong to 2026/Q1 and total \$8,400. The result has year and quarter in its index; reconciliation returns `True`. This confirms the observed sum in this dataset, not the correct inclusion of every possible identity or revenue amount on its own. No additional temporal API is needed.
