## Solution to Exercise 01

We need to make the library available before creating the object. `import numpy as np` establishes the short name used to call `np.array()`. The list in brackets supplies the four values, and the assignment stores the array in `costs`.

``` python
import numpy as np
costs = np.array([75, 82, 79, 91])
print(costs)
```

``` text
[75 82 79 91]
```

The output confirms four costs in the supplied order. Each number is in thousands of dollars: 75 represents USD 75 thousand. The array does not automatically store the unit of measurement; it comes from the problem definition and must accompany the interpretation.

<a id="sol-ch06-02"></a>

## Solution to Exercise 02

Each attribute answers a different question. Shape describes positions per dimension; `ndim` counts dimensions; `size` counts elements; and `dtype` identifies the storage type. We access attributes with a dot and no parentheses after their names.

``` python
print('Shape:', costs.shape)
print('Dimensions:', costs.ndim)
print('Elements:', costs.size)
print('Type:', costs.dtype)
```

``` text
Shape: (4,)
Dimensions: 1
Elements: 4
Type: int64
```

`(4,)` indicates one dimension with four positions, not a table with one row and four columns. `ndim` is 1 and `size` is 4. This environment reports `int64`; the historical output in the notes was `int32`. Both represent integers, and this expected difference changes neither the costs nor the exercise criterion.

<a id="sol-ch06-03"></a>

## Solution to Exercise 03

The first element uses index 0, while the last can be accessed with -1. Because indexing starts at zero, the second cost is at position 1. The assignment modifies that position in the existing array.

``` python
print('First:', costs[0])
print('Last:', costs[-1])
costs[1] = 84
print('Updated:', costs)
```

``` text
First: 75
Last: 91
Updated: [75 84 79 91]
```

The values read are USD 75 thousand and USD 91 thousand. After assignment, the array is `[75, 84, 79, 91]`: only the second cost changes, from 82 to 84 thousand. This updates the example data, unlike merely displaying a position.

<a id="sol-ch06-04"></a>

## Solution to Exercise 04

The slice `[:2]` starts at the first position and stops before index 2. The slice `[2:]` starts at that index and continues to the end. Both slices use the current state of `costs`, retaining the value 84 from the previous exercise.

``` python
print('First two:', costs[:2])
print('From the third element:', costs[2:])
```

``` text
First two: [75 84]
From the third element: [79 91]
```

The groups are `[75, 84]` and `[79, 91]`, in thousands of dollars. An output containing 82 in the first group would indicate that the earlier update was not retained. These statements only select and display values; they do not modify the array.

<a id="sol-ch06-05"></a>

## Solution to Exercise 05

We recreate the base specified in the prompt. Multiplying by 1.08 retains 100% of the value and adds 8%; adding 5 adds a fixed amount on the thousands scale. Each result receives its own name. The second calculation uses the base, not the result of the first scenario.

``` python
base_costs = np.array([75, 82, 79, 91])
increased_costs = base_costs * 1.08
costs_with_addition = base_costs + 5
print('8% increase:', increased_costs)
print('Addition of 5:', costs_with_addition)
print('Original:', base_costs)
```

``` text
8% increase: [81.   88.56 85.32 98.28]
Addition of 5: [80 87 84 96]
Original: [75 82 79 91]
```

In the proportional scenario, costs are 81, 88.56, 85.32, and 98.28 thousand dollars. In the fixed-addition scenario, they are 80, 87, 84, and 96 thousand. The final print confirms the original base. Broadcasting applies each scalar to every position; it does not turn these scenarios into forecasts of future costs.

## Solution to Exercise 06

We create both structures with the same values to isolate the difference in the operator’s meaning. The code keeps separate names and displays the results; we are not comparing execution times.

``` python
values_list = [12, 18, 25]
values_array = np.array([12, 18, 25])
print('List:', values_list * 2)
print('Array:', values_array * 2)
```

``` text
List: [12, 18, 25, 12, 18, 25]
Array: [24 36 50]
```

The list is repeated and now has six elements. The array still has three elements, now 24, 36, and 50, because each value was multiplied. The array expresses this numerical calculation more directly. That does not make lists unsuitable for other tasks or establish a measured performance advantage.

## Solution to Exercise 07

The condition is strict: “exceed” means `>`, not `>=`. Comparing the array with 50 applies the criterion at each position and returns one Boolean value per time.

``` python
import numpy as np
times = np.array([42, 55, 38, 61, 47, 70])
print(times > 50)
```

``` text
[False  True False  True False  True]
```

True positions correspond to 55, 61, and 70 minutes. The result is still an array of conditions with six positions, not the subset of three times. A value exactly equal to 50 would not satisfy the condition, although none occurs in these data.

<a id="sol-ch06-08"></a>

## Solution to Exercise 08

The comparison is unchanged, but its result now receives a name. The assignment lets us reuse the condition in the next selection and makes the Boolean array’s role explicit.

``` python
delay_mask = times > 50
print(delay_mask)
```

``` text
[False  True False  True False  True]
```

There are six Boolean values, one per observation. `True` means that the corresponding time exceeds 50 minutes; it does not represent the service duration. The mask’s name communicates the criterion adopted in this exercise.

<a id="sol-ch06-09"></a>

## Solution to Exercise 09

We place the mask inside the time array’s brackets. NumPy retains values at true positions and stores the result in `delayed_times`. The condition and the selected values are objects with different roles.

``` python
delayed_times = times[delay_mask]
print(delayed_times)
```

``` text
[55 61 70]
```

The selection contains 55, 61, and 70 minutes in that order. The original array has six elements; the subset has three. Selection is not a sum, a mean, or a sorting operation: it simply retains observations meeting the criterion.

<a id="sol-ch06-10"></a>

## Solution to Exercise 10

We apply the methods to `times`, not to the `delayed_times` subset. All four metrics therefore describe the six observations. The mean divides the sum of all values by six.

``` python
print('Total:', times.sum())
print('Mean:', times.mean())
print('Minimum:', times.min())
print('Maximum:', times.max())
```

``` text
Total: 313
Mean: 52.166666666666664
Minimum: 38
Maximum: 70
```

The total is 313 minutes, the mean is approximately 52.17 minutes per observation, and the extremes are 38 and 70 minutes. The mean’s long decimal representation comes from floating-point calculation; a rounded interpretation does not change the data. Do not confuse this overall mean with the mean only for times above 50.

<a id="sol-ch06-11"></a>

## Solution to Exercise 11

We reconstruct all three steps to make the reasoning visible. `times > 50` produces the condition; `times[delay_mask]` forms the subset; `size` counts its elements, and `mean()` calculates its mean. The size attribute has no parentheses, while the mean method does.

``` python
delay_mask = times > 50
delayed_times = times[delay_mask]
delay_count = delayed_times.size
delay_mean = delayed_times.mean()
print('Count:', delay_count)
print(f'Mean above 50: {delay_mean:.2f} minutes')
```

``` text
Count: 3
Mean above 50: 62.00 minutes
```

Three observations meet the criterion, with a mean of 62 minutes. The `.2f` specification only displays two decimal places. This subset is nonempty, so its mean has a direct interpretation; an empty selection should not be assigned a mean of zero.

<a id="sol-ch06-12"></a>

## Solution to Exercise 12

“USD 27 or more” includes 27 itself, so the mask uses `>=`. We sum selected values in the numerator and all reported values in the denominator. Multiplying the ratio by 100 expresses it as a percentage. The denominator is positive in these data.

``` python
costs = np.array([18, 24, 31, 27, 35, 22])
high_cost_mask = costs >= 27
high_costs = costs[high_cost_mask]
share = high_costs.sum() / costs.sum() * 100
print('Selected costs:', high_costs)
print(f'Share: {share:.2f}%')
```

``` text
Selected costs: [31 27 35]
Share: 59.24%
```

The selected values are 31, 27, and 35 dollars, which sum to 93. The six unit costs sum to 157, and 93/157 is approximately 59.24%. This metric describes a share of that sum, not a share of total spending weighted by unknown quantities. It is also not the proportion of selected observations: three out of six would be 50%, answering a different question.

## Solution to Exercise 13

Each inner list provides one production line’s output across three shifts. The outer list groups the four production lines. After creation, we inspect the attributes to check that the structure matches the case description.

``` python
import numpy as np
production = np.array([
    [480, 510, 495],
    [520, 505, 530],
    [450, 470, 460],
    [550, 545, 560]
])
print('Shape:', production.shape)
print('Dimensions:', production.ndim)
print('Elements:', production.size)
```

``` text
Shape: (4, 3)
Dimensions: 2
Elements: 12
```

Shape `(4, 3)` represents four production lines and three shifts. `ndim` is 2 because the data have two dimensions; `size` is 12 because 4 × 3 = 12. Each observation is a line-shift combination measured in units produced. The number of dimensions is not the number of production lines.

<a id="sol-ch06-14"></a>

## Solution to Exercise 14

We want to retain one answer for each of the four lines. We therefore combine the three shifts within each line, reducing the column dimension with `axis=1`. The destination variable names the meaning of the four totals.

``` python
production_by_line = production.sum(axis=1)
print(production_by_line)
```

``` text
[1485 1555 1380 1655]
```

The lines produced 1,485, 1,555, 1,380, and 1,655 units, respectively. The result has four elements, as expected for a question by line. These totals aggregate shifts; they are not values for a single line-shift combination.

<a id="sol-ch06-15"></a>

## Solution to Exercise 15

We now want one result per column, corresponding to each shift. We therefore combine the four production lines using `axis=0`. The axis changes because the question changes, while the data remain the same.

``` python
production_by_shift = production.sum(axis=0)
print(production_by_shift)
```

``` text
[2000 2030 2045]
```

Totals are 2,000, 2,030, and 2,045 units for the three shifts. In Exercise 14, we reduced shifts to retain lines; here, we reduce lines to retain shifts. Reading the shape and the case labels is more reliable than memorizing an axis as an isolated word.

<a id="sol-ch06-16"></a>

## Solution to Exercise 16

“Below” corresponds to `<`. The comparison preserves shape 4 × 3 and produces one condition for each line-shift combination. Applying the same-shaped mask to the array gives a one-dimensional sequence of selected values. `size` counts the elements of that sequence.

``` python
target = 500
below_mask = production < target
below_production = production[below_mask]
print(below_mask)
print('Values below:', below_production)
print('Count:', below_production.size)
```

``` text
[[ True False  True]
 [False False False]
 [ True  True  True]
 [False False False]]
Values below: [480 495 450 470 460]
Count: 5
```

The values are 480, 495, 450, 470, and 460 units. These are five observations: two in Line 1 and three in Line 3, visible in the mask. They are not five production lines or five distinct shifts. Selection follows the true positions; it does not sort production from smallest to largest.

## Solution to Exercise 17

The factor 1.03 combines the original value with a 3% increase. Multiplication applies that scalar to every element through broadcasting. Storing the result in `scenario_production` keeps `production` available as a comparison base.

``` python
scenario_production = production * 1.03
print(scenario_production)
print('Original preserved:')
print(production)
```

``` text
[[494.4  525.3  509.85]
 [535.6  520.15 545.9 ]
 [463.5  484.1  473.8 ]
 [566.5  561.35 576.8 ]]
Original preserved:
[[480 510 495]
 [520 505 530]
 [450 470 460]
 [550 545 560]]
```

The first observation goes from 480 to 494.4 in the scenario, and the last from 560 to 576.8. The second print confirms that the base remains intact. Fractions are results of the arithmetic assumption, not instructions to manufacture fractions of products. An operational rounding policy would require additional information and has not been invented here. The scenario does not forecast future production.

## Solution to Exercise 18

The totals by axis and the selection have already been constructed. We now calculate the mean of the below-target subset and sum all positions in the scenario. The report combines these objects; it should neither replace the subset mean with the overall mean nor apply the 3% factor again.

``` python
below_mean = below_production.mean()
scenario_total = scenario_production.sum()
print('Boreal Manufacturing')
print('Totals by line:', production_by_line)
print('Totals by shift:', production_by_shift)
print('Observations below target:', below_production.size)
print(f'Mean below target: {below_mean:.2f} units')
print(f'Total production in the 3% scenario: {scenario_total:.2f} units')
```

``` text
Boreal Manufacturing
Totals by line: [1485 1555 1380 1655]
Totals by shift: [2000 2030 2045]
Observations below target: 5
Mean below target: 471.00 units
Total production in the 3% scenario: 6257.25 units
```

An interpretive report might state: the four lines total 1,485, 1,555, 1,380, and 1,655 units, reducing shifts with `axis=1`; the three shifts total 2,000, 2,030, and 2,045, reducing lines with `axis=0`. The mask `production < target` selects five of the 12 observations, whose mean is 471 units. Line 3 has the lowest total, 1,380, and warrants monitoring. This does not identify the cause of the difference. In the hypothetical scenario, total output rises from 6,075 to 6,257.25 units, without a rounding policy or any guarantee that it will occur.
